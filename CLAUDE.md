# Task System

## Project

Open-source C++ task/scheduler system, generic but game-engine-focused. Inspired by Unreal Engine's Tasks System (which the author designed and implemented at Epic Games), with improvements and additional functionality. Goals: UX, performance, rich functionality.

## Author

Experienced engine programmer. Designed and implemented UE Tasks System at Epic Games. Expects expert-level C++ discussion — no hand-holding, no over-explaining idioms.

## Stack

- C++23 (MSVC/clang-cl on Windows, Visual Studio solution)
- No external dependencies
- Lock-free/low-contention concurrency preferred

## Current State

Four layers, all built and tested (the harness suite, the sample, and the benchmarks all pass). Sources: public headers in `include/ts/`, internal headers in `include/ts/detail/`, implementation in `src/`, plus `tests/`, `benchmarks/`, `sample/`.

- **`ts::Scheduler`** (`scheduler.{h,cpp}`, `worker_thread.{h,cpp}`; the whole scheduler layer — `Scheduler`, `Scheduler_config`, `Idle_policy`, `Priority`, `current_scheduler`/`current_worker_index`, and the queue/deque/eventcount internals — lives in `ts::`/`ts::detail` like the rest of the library) — priority queue + `std::jthread` worker pool. `Priority {high, normal, low}` (in `priority.h`, shared with the task core) orders the queue; every queued task route threads a priority to `submit`: `ts::launch(fn, {.priority=p})`, `ts::task(fn).priority(p)`, `Guarded::async(fn, {.priority=p})`, `Graph_node::priority(p)` — stored on the block, applied at dispatch (incl. prerequisite-gated). `parallel_for`/`async_parallel_for` helpers inherit the calling task's priority by default (`current_task->flags.priority`, resolved once on the calling thread; `Priority::normal` outside a task) — `Parallel_options{.priority}` overrides; the participating caller runs inline regardless. Per-instance `Idle_policy` via `Scheduler_config` at construction (runtime enum, no measurable hot-path cost), three modes: `spin` = never park, yield-loop (producers never signal); `spin_then_block` (**default**, UE-style) = spin `spin_cycles` scans on the `Event_count` (eventcount, not a semaphore) before parking, producer wakes one per submit (`spin_cycles == 0` degenerates to park-immediately); `handoff` = Go-style spinner handoff (a spinner that finds work promotes a successor before running; producer issues the wake syscall only on the fully-parked 0→1 transition, else a cheap epoch bump — moves wake cost off the producer). Wake latency ~40% lower than a bare park; throughput cost on uncontended streams. See `signal_submit`/`handoff_wait` in `scheduler.cpp`. Runtime, not templated — the `thread_local Scheduler* current_scheduler` rules out templating `Scheduler`. The single mutex-guarded `std::priority_queue` is the known scaling bottleneck (benchmarks confirm). **Busy counters (`TS_PROFILING`)**: per-worker padded `Busy_slot` (completed `ticks` + in-flight `started` — the in-flight part matters: a trace's fold runs INSIDE the settling worker's task, so completed-only counting reads 0 on a 1-worker scheduler); `run_task` times each task ONLY while armed (`arm_busy_tracking` refcount, armed by a traced run's window — disarmed cost is one relaxed load+branch, unmeasurable on the spin throughput series; armed = 2 clock reads/task); `busy_ticks()` = relaxed sum + in-flight elapsed, feeds the trace's core-utilization metric.
- **`Guarded<T>`** (`guarded.{h,cpp}`) — the access-controlled wrapper; the only sanctioned way to touch a thread-unsafe `T` across threads. Two verbs run `fn(T&)` (write) or `fn(const T&)` (read) on a per-object **reader/writer pipe** (concurrent readers, exclusive writer, FIFO, completion-driven dispatch), mode deduced from the functor's parameter const-ness: **`access(fn, opts={})`** is opportunistic — it runs the body **synchronously on the calling thread** when the pipe is immediately free (`pipe_try_inline` — reader joins as a reader, writer exclusive; never jumps queued work), else enqueues; **`async(fn, opts={})`** always enqueues (for heavy functors). `access` may briefly block the caller and stacks its access scope, so prefer `async` for non-trivial work inside a graph node. The verb IS the mode: neither reads `run_inline`. Options are an `Access_options` aggregate (`{.token, .priority}`, in `task.h`) — deliberately split from `Task_options` (`{.token, .priority, .run_inline}`, used by `then`/task builders) so passing `run_inline` to an access verb is a compile error, not a silent no-op. Constructs `T` in place; adopting an existing instance is future work. **Multi-object**: the free functions `ts::access(fn, objs...)` / `ts::async(fn, objs...)` (options first: `ts::async({.priority=p}, fn, objs...)`) run `fn(*obj1, *obj2, ...)` over several `Guarded`s at once — per-arg mode from const-ness (`Function_traits`), acquiring each object's pipe mode-aware in **canonical (pipe-address) order, holding** (`multi_acquire`, the same `pipe_acquire`/`pipe_release` primitive as the graph — shared address order, so nodes and multi-object accesses can't deadlock), running under an `Access_context` declaring all, then releasing at completion (`attach`). Deadlock-free by ordered acquisition; dedups a repeated object (write-wins). Multi-object `access` behaves like `async` for now (the multi-object inline fast path is a follow-up). **Access-mode deduction, one spelling rule everywhere (A3+A4, 2026-07)**: non-generic functors are introspected (`Function_traits`; by-value / `T&&` resource params are `static_assert`-rejected — a copy silently discards writes); **generic lambdas deduce too**, via the rvalue-bindability probe (`detail::probed_mode` — `const auto&`/`auto&&` binds an rvalue → read, `auto&` cannot → write), so `[](const auto& p, auto& a)` works bare, no tags. Every READ position (deduced/probed/tagged) invokes the body with `const T&` (`detail::mode_ref`), so mutating under a read classification is a compile error. Constraint/return-type ORDER is load-bearing: the mode gate (`accessor_mode`, `Accessor_result`) is evaluated before any invocability probe against `const T&`, because probing a generic lambda deduces its return type → instantiates the body → hard error for a mutating body (not SFINAE). Residual: generic `auto` by-value probes as a read and copies — undetectable, documented. `ts::as_read_only(g)`/`as_read_write(g)` tags (`detail::Access_arg<T, M>`) remain as explicit style, the `auto&&`-that-writes escape, and legal write-over-declaration; all args tagged or none (mixing is a `static_assert`); applies to `ts::access`/`ts::async` and graph `add_node`. One unified builder per surface: `async_build_modes` / `fill_node_modes` (deduced/probed/tagged tiers).
- **`Task<R>`** (`task.h`) — async result handle, the single representation for every result-bearing producer (`async`/`then`/`when_all`/`execute`): `sync()` (call once), `is_done()`, `then(fn, opts={})` (continuation — a **proper scheduled task** with the producer as a `num_locks` prerequisite, queued by default so it gets a priority and the scheduler can interleave; a `Task_options` aggregate carries `{.token, .priority, .run_inline}` so a `then` dispatches inline / at a priority / with its own cancel token, same as a builder task). `ts::launch`/`ts::nested` take a `Launch_options{.token, .priority}` (no `run_inline` — a bare task has no settling thread; inline is a builder capability). `when_all(tasks...)` joins typed prerequisites into `Task<tuple<...>>` — void prerequisites are pure ordering and drop out (all-void → `Task<void>`); non-void results are moved into the tuple (move-only supported); consume via `then([](tuple&){...})` or apply-style `then([](A& a, B& b){...})`. `Task` is a completion handle only — it does not carry graph identity (see `Graph_node`). The shared state is a **fully monomorphic** `detail::Task_control_block` (not templated at all — the result is erased behind `void* result_ptr` and composed via a `Result_block<R>` wrapper the handle `shared_ptr`-aliases; no `<void>` specialization; no virtual dispatch). The **body** lives in the block too: `async` and `ts::launch(fn)` (standalone, no access target) store it in an `Executable<Body,R>` wrapper reached via a `core.execute` fn-ptr (body type erased, block stays monomorphic). **Prerequisites** via the block's lock-counter (`num_locks` + `successors`): `ts::task(fn).after(x, y).launch()` runs once every prerequisite has *settled*; a **cancelled prerequisite propagates** — it releases the dependent but marks `prereq_cancelled`, so the dependent settles cancelled instead of running (uniform with `then`, via the block's `prereq_cancelled` flag checked in `Executable::run`). `detail::submit_ready` bridges the counter to the scheduler. This is the same mechanism as the graph's indegree (the graph/`when_all` rebase onto it is pending). **Reusable tasks**: no new type — `Task_control_block::reset()` re-arms a settled block in place (monomorphic, scalars only), and the `Task_builder<R>` from `ts::task(fn)` is the reusable handle (it retains the block after `launch()`; also has `reset()`/`sync()`/`is_done()`): `t.reset().after(x).launch(); r = t.sync()` re-runs one block/body/result-storage (one run in flight; `reset()` guarded by the block's `ready` flag). `Signal::reset()` gives a reusable phase gate. **Nested tasks**: `ts::nested(fn)` / `ts::add_nested(task)` (via a `current_task` TLS) from inside a running body gate the parent's completion — the `num_locks` `execution_flag` bit flips it from counting prerequisites to counting nested tasks. **Retraction**: a blocking `sync()` on a *retractable* (bare `launch`/`task`, not pipe/`async`), ready, not-yet-started task runs it **inline** on the waiting thread (a `started`-claim keeps a worker and the retractor from both running it) — this breaks the oversubscription deadlock (nested fork-join blocking all workers). **Deep**: `sync()` on a dependent walks its `prerequisites` (backward links) and runs the whole un-started subtree inline, so waiting on a join (not just leaves) is deadlock-free too. **Inline dispatch**: `ts::task(fn).set_inline().after(...)` runs a ready task on the thread that settled its last prerequisite (not the queue) — the dispatch forks in `release` (`dispatch_ready`), bounded by a per-thread FIFO trampoline (`inline_pending` + head index) so deep inline chains don't recurse; caveats (nondeterministic/external thread, bypasses priority, must not block) are documented not enforced. Static dispatch bits (`priority`/`retractable`/`run_inline`) are packed into a `Flags` byte on the block. See `docs/task-internals.md` §2/§4/§6/§7. **`Signal`** is a bodyless `Task<void>` completed by hand via `trigger()` (idempotent) — an integrated done-signal / barrier / phase gate (UE's `FTaskEvent`). **Cancellation**: `Cancellation_source`/`token` (cooperative); `async`/`then`/`execute` take an optional token; not-yet-started work is skipped and cancellation propagates down continuations/successors as a completion state (`Task::is_cancelled()`); a cancelled value `sync()` is fatal (check first), a cancelled `void` sync() unblocks. **Body-level early-out (opt-in)**: any task body that declares a trailing `Cancellation_token` parameter (`[](Cancellation_token t){...}`, `[](T& v, Cancellation_token t)` for `async`, or a `then` continuation in any shape) receives the block's token (forwarded by `Executable::run`; `Task_result_t`/`Async_result_t`/`Invoke_result_tok` derive the result type off the token-arity overload) so it can poll `is_cancel_requested()` and early-out for cancellation arriving *mid-run* — a cooperative return settles the task **completed**, not cancelled. Covers `task`/`launch`/`nested`/`async`/`then`. A cancelled `when_all` prerequisite cancels the join (it can't form a tuple) rather than stalling. **Push notification**: `Cancel_callback(token, fn)` (RAII, `std::stop_callback`-style) — `request_cancel()` fires registered callbacks synchronously, for work that blocks rather than polls; source/token/callback share a `detail::Cancel_state` (atomic flag + mutex-guarded callback list).
- **`Static_task_graph`** (`static_task_graph.{h,cpp}`) — build-once / run-many DAG. **Node naming + structure dump**: `add_node` takes an optional leading `Node_name` (implicit from a static literal — `add_node("physics", fn, objs...)`; `{}` captures the `add_node` call site via `std::source_location`, labeling `file:line`; a defaulted param after the object pack is not expressible in C++, hence the leading position, UE-style); names are kept in shipping builds (one `const char*`/node). `compile(DOT_path)` (default null) writes the compiled DAG as Graphviz DOT via the header-only `tools/dot_writer.h` (`ts::tools::DOT_writer`), dark monokai-derived theme: green edges (`#a6e22e`), line style = provenance — solid (penwidth 2.0) = explicit `after`/`before`, dashed (penwidth 1.8) = conflict-derived — with the object+modes as SVG hover tooltip (`obj3: W->R`); an edge that is both renders explicit-styled with the conflict tooltip; unnamed un-sited nodes label `node<N>`. Objects are named via `ts::Named` — an optional leading ctor arg on `Guarded`/`Versioned` (`Guarded<T> g{ts::Named{"physics"}, args...}`; a distinct wrapper so it can't be mistaken for `T`'s first ctor arg; stored as `Pipe::debug_name`, kept in shipping) — so derived-edge tooltips read `physics: W->R`; unnamed objects fall back to `objN` ordinals. **Runtime trace (aggregated, no samples)**: `set_trace(tools::Graph_trace*)` (requires compile(); nullptr detaches; forward-declared in the public header, only the .cpp includes `tools/graph_trace.h`) — the graph's whole involvement is a cpp-local `Trace_stamps` class (pre-sized arrays; `steady_clock` ticks — ready at the dep-counter zero transition, start/end around the body — + worker index, armed per run only when attached; every method a no-op under `TS_PROFILING=0`, so the run logic carries no `#if`s) with 4 mark calls and ONE `stamps.fold` call at run settle (settling thread, before `done` settles so a sync()ed caller reads a consistent trace; cancelled runs skipped; recompile re-pushes structure and resets aggregates). `Graph_trace` (header-only, `tools/graph_trace.h`) streams per node Welford mean/var + P² P50/P95 + min/max + per-worker histogram + dispatch wait (ready→start = acquire+queue latency) + critical-chain counter, per edge the mean meet point `(end_u+start_v)/2` + a chain counter, global makespan + critical work — O(nodes+edges) state. **Measured critical path**: per run, a backward walk from the latest-finishing node through the binding predecessor (latest-end in-edge) counts chain membership; aggregate = criticality FREQUENCY (no single path across variable runs), rendered as a colour blend by share — node border+label cyan→orange, edge green→pink (dash keeps carrying provenance; widths uniform) — with legend rows. A CPM pass (median durations, zero latency) at `write_SVG` yields per-node slack (structural bound; divergence from the measured chain = scheduling-bound, not dependency-bound). Validated on game_frame: the spine input→networking→trio(economy-dominant)→AI→animation→propagation→flip→culling/particles→submit at 100%/split shares, off-path nodes 0%. `write_SVG(path)` renders the AVERAGE run: median bars packed into anonymous concurrency rows (greedy interval packing by bar start — rows carry NO worker identity, since assignment reshuffles per run and modal lanes misread as idle cores; row occupancy over time = average concurrency; no row labels), edges connecting them (same monokai styling); critical dead-time waits draw as full-height hatched+tinted pink bands ending at the waiting node's bar start (the wait is a chain property, not a row's; background + pointer-events none), formatted hover tooltips via a self-contained overlay script embedded in the SVG (document context only, inert under `<img>`; headline in the element's colour, bold field names) = stats (mean/P95/σ/CV/min–max; no worker line — workers are interchangeable) + priority + declared accesses; bars carry the node's queue priority as a letter at the right end (red H / green N / grey L; `#ff5f45` for H — distinct from critical pink/orange; narrow bars append it to the outside label); `set_title` prefixes the header (the sample sets `Sample "game_frame"`); medians aren't linear so edge-crossing bars are clamped to the edge's mean meet point (topo order); time-overlapping bars split rows by construction (with MEAN bars edge crossings are impossible by linearity, see design.md §2.3). Gated by `TS_PROFILING` (defined in `static_task_graph.h`, default 1; =0 compiles the dump + trace out, the parameters stay). Driver: `task_system --dot [path]` (default `sample_game_frame.dot`) dumps the game_frame graph (19 named nodes, all stores named); `task_system --trace [n]` runs n frames traced TWICE — default scheduler and a dedicated 4-worker one (starved lanes exercise same-lane stacking, handoff welds, dead time) — headline classifiers on the SVG: core utilization first (busy delta / `workers × window` from the scheduler's armed busy counters; ≥75% green / <50% red; inline non-worker work uncounted) then critical dead time (<5% green / >10% red), banded constants at the top of `graph_trace.h` — writing `sample_game_frame_avg.svg` + `sample_game_frame_avg_4workers.svg` + the DOT; `show_graph.bat [file.dot]` (repo root) renders and opens — no-arg does the whole sample_game_frame set. `add_node(fn, Guarded<>&...)` deduces per-arg access from the functor's parameter const-ness (`Function_traits` for non-generic functors; the rvalue probe for generic lambdas — `const auto&` = read, `auto&` = write; or explicit `ts::as_read_only`/`as_read_write` tags — see `Guarded`, "one spelling rule") and returns a `Graph_node` — a build-time ordering handle (`after`/`before`), not a completion handle (run-many means a node has no single result). `compile()` derives edges from access conflicts (shared instance + at least one writer, ordered by declaration index) plus explicit `after`/`before`, dedups, Kahn cycle-checks. `execute()` runs the DAG in parallel via atomic indegree counts; re-runnable; returns a completion `Task<void>`. Each node runs as a real task block (a `Graph_node_block`, §7.1), so its body may spawn **nested tasks** (`ts::nested`) — its completion (and thus its successors + object release) gates on them — and nested sub-work inherits the node's `Access_context` by value (`ts::launch` snapshots it), so it may touch the node's owned guarded data. Node blocks + the `Run_state` are built at `compile()` and re-armed per run (nodes dispatch via the raw scheduler API; completion via the block's persistent `on_complete` fn-ptr, not a per-run continuation), so a run allocates only its `done` handle — re-runs are essentially allocation-free (~19% faster than per-run blocks). The graph is movable (`execute()` refreshes the blocks' back-pointers); runs are sequential (one at a time). Nodes access their objects **directly** (bypassing the pipe), so each node **acquires** the objects it touches (`pipe_acquire`/`pipe_release`, mode-aware) before running and releases them at completion — a concurrent `Guarded::async` on the same object queues behind the node that holds it instead of racing it (the harness does *not* catch that race — both sides declare access). Acquire is **per-node, mode-aware, canonical-order incremental** (ascending pipe-index; deadlock-free): an object is held only over each accessor's `[acquire, complete]` window — free in the gaps for async (a gap node between two accessors leaves it free), and a **reader** node holds it as a reader so a concurrent async read (or another reader node) overlaps; a **writer** node is exclusive. Replaces the old whole-run writer-only reservation. **Inline dispatch** (`Graph_node::set_inline()`): a ready node runs on the thread that settled its last prerequisite when it can acquire all its objects *synchronously* there (via the shared `dispatch_ready` trampoline); a contended object defers it to the queue — the "revoke predecessor's access, acquire successor's, else defer" hand-off. **Object handoff**: `node_complete` hands a held object *directly* to the sole ready successor that takes it in the same mode (skip release + re-acquire — the pipe state is already right; a `preheld` bitmask makes the successor's `acquire_next` skip it), instead of the release/re-acquire round-trip; unique for writers by the conflict edges. Non-handoff objects are released (the gap-freeing). See `docs/task-internals.md` §10 for the mechanism + the scenarios that still break (blocking on same-object async in a node, concurrent/nested runs on shared objects, incomplete declarations).
- **`Deferred<T>` / `Versioned<T>`** (`journal.h` + `deferred.h` + `versioned.h`, header-only; `journal.h` holds the shared staging machinery — `detail::Journal`, `Recorder`, `Parallel_recorder`) — the deferred-write layer from `docs/command-buffer-design.md` (design 4, implemented; vocabulary: **stage / commit / publish**). `Deferred<T>` binds to a `Guarded<T>`: `recorder()` mints move-only producer handles whose `stage(closure)` appends to private per-recorder storage (**no grant on the target**, contention-free between recorders — `detail::Journal<T>`, shared machinery); `commit_async(opts)` applies everything as ONE ordinary pipe write (cut at execution time, so a cancelled commit retains its commands), `commit(T&)` applies under a write grant the caller already holds (graph node / async body — checked via `access_check`). Apply order is deterministic: recorder-creation order, FIFO within — independent of thread timing. Producer→commit ordering is hand-wired (`after`); `Access::append` edge derivation is deliberately deferred. `Versioned<T>` = journal + two replicas behind one `Guarded` front (readers declare ordinary read on `state()`; the swap exchanges CONTENTS, so the front's address is stable — zero graph/pipe/harness changes): `read()` sees the last published version all frame (no read-your-writes — outputs arrive as the NEXT version), `publish()` is a **three-phase** step where only the swap holds the write grant — (1) cut + apply to shadow, grant-free; (2) swap, ~ns; (3) resync as a **pipe read job**, overlapping readers of the new version while FIFO holds the next writer (incl. a graph flip's acquire) behind it — the pipe is the shadow-ownership chain; consecutive publishes also chain phase 1 after the previous resync internally (an empty publish doubles as a resync fence). **Single-publisher enforcement**: a graph/inline publish catching an unresolved dynamic publish is fatal at flip entry (`TS_SAFETY_CHECKS`); a SYNCED publish before a run is deterministically legal (the swap enqueues the resync before triggering the phase gate, so the flip pipe-orders behind it), and a dynamic publish arriving mid-flip chains behind the flip. Graph form: `ts::publish_body(v)` as a node with write on `v.state()`. Resync policy per instance: `replay` (default — re-apply the batch; both applications see bit-identical pre-states, so deterministic commands give bit-identical replicas; **commands must be deterministic**), `copy` (user fn or copy-assign), `overwrite` (writer rewrites everything; no resync). `set_divergence_check(hash)` fatals on replica mismatch after replay (bitwise — replay has no FP drift on one binary). Staged-but-unapplied commands at destruction are **fatal** under `TS_SAFETY_CHECKS` (lost writes); `discard()` is the escape. Selection rule: `Versioned` is for state whose per-frame delta is *data*; when producing version N+1 is heavy computation (physics sim), keep ONE instance behind `Guarded` and version its output *extract* — see `sample/physics.cpp` (sealed `Guarded<Physics_world>` with a single grant holder — the sim's write; `Deferred` inputs, `Versioned` pose snapshot, id-reservation forward refs, batch-extract idiom; deterministic across runs). Known v1 costs: closure-tier commands (`move_only_function`, per-command alloc past SBO — typed-POD/arena tier pending, alloc-audit), per-slot mutex on stage (uncontended one-producer use; exists for the dynamic stage-vs-cut race). **Parallel staging**: `parallel_recorder()` mints a per-WORKER handle (slots keyed by the scheduler's `current_worker_index` TLS + an overflow lane for non-worker threads — the `parallel_for` caller's share, retraction/inline bodies) for ONE producer parallelized internally: contention-free under any chunking (guided/stealing/long tail), but cross-thread apply order is nondeterministic — use it for per-key-single or commutative commands (or a sorted commit); index-keyed `Recorder` lanes remain the raw-determinism answer. Batch order is still fixed at the cut, so `Versioned` replay stays exact either way. **Ordering contract** (journal.h): intra-recorder FIFO is semantic — build on it; **cross-recorder order is arbitrary — never build semantics on it** (same-key cross-producer writes are a conflict; fix = one writer per key / commutative commands / future sort keys), but it IS deterministic given a deterministic mint/destroy sequence, so runs are reproducible (bugs included). Recorder dtors release their slots to a free-list (live slots bounded by peak concurrent recorders — mint/destroy per frame no longer grows the journal; staged-but-uncut commands survive release); a reused slot keeps its position — observable only to programs already violating the contract. Keeping >4096 recorders alive is fatal under `TS_SAFETY_CHECKS` (`Journal::max_slots` — catches mint-and-retain-per-frame). Recorders must not outlive their `Deferred`/`Versioned` (dtor touches the journal). **Pattern recipe — blackboard**: no new type; shared board = `Versioned<Blackboard>`, private board = plain member, key-change notification = dispatch node after the flip + per-subscriber value diff (doc §7.4; single-file sample `sample/blackboard.cpp`).
- **Access harness** (`access.{h,cpp}`) — `TS_CHECK_ACCESS()` at the top of every guarded method checks `this` against a thread-local `Access_context` the scheduler/pipe installs per task; a violation routes to `ts::fatal`. ~1 ns/call. Subtasks (e.g. `parallel_for` chunks) inherit the parent node's context. Gated by `TS_SAFETY_CHECKS`.
- **`fatal.{h,cpp}`** — exceptions are disabled project-wide; all non-recoverable failures call `ts::fatal` (message + `std::stacktrace` + `abort`). Tests are the one place failures are non-fatal (the harness records and continues); fatal paths are checked via subprocess death tests.
- **Samples** (`sample/`) — three SINGLE-FILE, self-contained .cpp samples (no headers — consumers forward-declare the entries; the blackboard convention, now the rule). `game_frame.cpp`: a ~30-system mock game-engine frame built in TWO variants from the SAME system bodies via `build_frame_graph(World&, Frame_variant, dot)` — `baseline` (straightforward composition) and `optimised` (levers applied in an `optimise()` section + branched node bodies), the worked optimisation exercise in [docs/example-frame-optimization.md](docs/example-frame-optimization.md). Exercises every layer — schedule derived from declared access, a frame head (camera/networking/scripting), gameplay trio, AI (speculative cancellable nav queries, trailing-`Cancellation_token` early-out), animation chain (graph→IK→skinning), split physics pipeline (broadphase→narrowphase→solver→finalize; the multi-conflict `physics→propagation` edge via velocities+bodies), a RENDER pipeline reading LAST frame's transforms via `Versioned<Transforms>` so it overlaps sim (the render-thread-with-one-frame-latency model), off-path leaves (vfx/replication/stats/gc/navmesh_rebuild), `ts::parallel_for` in heavy systems, streaming via `async`+`then`+`when_all`, a per-frame HUD snapshot via multi-object `ts::async(fn, combat, economy)`, one bare generic-lambda node (`const auto&` probe). Priorities are IDENTICAL in both variants (kept for their visualization, NOT a lever — compilation ignores them). The optimised levers, all tool-guided from the baseline trace: (1) AI reads LAST frame's gameplay via a second `Versioned` snapshot (the gameplay trio's results staged + flipped at frame end) — deletes the `trio→AI` edges, the SINGLE BIGGEST cut (−821 µs), the marquee dependency-cut lever; (2) parallelise the fattest serial CRITICAL bars (`combat`/`ik_post`/`UI` — critical-path-bound, so splits move the makespan); (3) `Deferred` draw staging (producers go wide — utilization, NOT makespan); (4) cloth on prev-frame transforms (off the post-flip tail; neutral on the long spine, fills cores once the spine is short). Baseline 4793 µs / 60% util / 5% dead → optimised 3120 µs / 85% util / 19% dead (−35%) on 6 workers — the picture flips from dependency-bound (cores idle, chain never waits) to CORE-bound (cores full, chain waits for a core; the single critical spine fragments), the "optimisation is done" signal. `transform0==5` determinism held both variants. `--trace` traces both variants on a `variant_workers`(=6)-worker scheduler → `sample_game_frame_avg_baseline.svg` + `sample_game_frame_avg_optimised.svg` + the DOT. ## Terminology

Use these terms precisely, in code and discussion:

- **spin waiting** — yielding in a loop until a condition holds (e.g. the worker idling on an empty queue, or a fixed-duration `spin()`). Does no other work.
- **busy waiting** — doing *unrelated* work while waiting, e.g. a thread that pops and executes other queued tasks while waiting for a specific task to complete. Usually a bad idea (stack growth, latency, priority inversion). Not the same as spin waiting.

## Design Principles & Lessons

- **Granularity decides parallelism.** Whole-object (system-level) access serializes every reader against any writer, collapsing the DAG toward sequential. Shard mutable state — the sample double-buffers transforms (`world_xf_prev` read by early systems, `world_xf` written by propagation and read by late systems, swapped per frame) so many readers don't contend with the writer. The central tension: static safety wants coarse access sets, performance wants fine ones.
- **Completeness hazard.** The graph's safety holds only if its access declarations are *complete*. A manual task or an escaped reference touching a system the graph believes it owns races — and the graph can *promote* a latent bug to a live one by manufacturing parallelism around it. The harness is the runtime oracle for undeclared access.
- **Never block inside a graph node / task.** Cross-system async access is fire-and-forget; consuming a result needs a continuation into a downstream node, not a `sync()` inside the node. Blocking ties up a worker and risks deadlock under worker exhaustion.
- **Sync state shared across threads must outlive every participant** — heap it (`shared_ptr`), never leave it on a stack frame the initiator may unwind first. (This cost a real use-after-free in `parallel_for`: the caller returned on `completed == chunks` and unwound while a helper still touched the stack counters.)
- Prefer per-instance runtime config over templating when a `thread_local` singleton would fracture across instantiations. Prefer a counting semaphore over a condition variable for worker wake (decouples from the queue mutex; survives a future lock-free queue). Prefer intrusive / zero-alloc on hot paths; avoid virtual dispatch.
- **Prefer intrusive ref-counting over `std::shared_ptr` for types we control.** Use the generic `detail::Ref_counted<T>` (CRTP base) + `detail::Ref_ptr<T>` handle + `detail::make_ref<T>()` in `ref_count.h`: one allocation (not two), a one-pointer handle (not two words), fewer atomics. Reserve `std::shared_ptr` for interop with external types. `Task_control_block`/`Task_ptr` keep their own hand-rolled variant (it aliases inside `Result_block`/`Executable` wrappers, so it needs a `destroy` thunk rather than `delete T*`). Converted so far: `Cancel_state`, `Multi_async_state`, and `when_all`'s `Join_state`.
- **Allocation discipline (hot paths).** Never spray separate heap allocations for individual small fields — `when_all` did this wrong (four `make_shared` for a slots tuple, an `atomic<int>`, an `atomic<bool>`, and a `std::function`, plus two blocks = ~6 allocs/join, the worst per-op offender). **One state struct, one allocation** (ideally the intrusive block itself); fold counters/flags/continuations in as members. A per-type recycling free-list is trivial because each `Exec<Body,R>`/`Result_block<R>` instantiation is a *constant* size (variable across types, const per type). Reserve bump/linear (arena) allocation for provably scope-bounded lifetimes (a `parallel_for`, a graph run, a frame with no escaping tasks). Prefer a tunable-SBO callable over `std::move_only_function`/`std::function` (size the inline buffer to the common task-functor size so the closure never heaps), and small-vector (inline capacity) or intrusive links for the block's `successors`/`prerequisites`/`continuations` (usually 0–1 elements). See `docs/TODO.md` 3.1 for the ranked plan.
- **Debugging flaky crashes**: localize with `main`'s `--tests` / `--bench` / `--stress`, categorize exit codes (1 = a `TS_CHECK` failure via `summary()`; `0xC0000005` = an access violation), and build `/p:EnableASAN=true` to get the faulting stack. Get the stack before theorizing — inspection alone misled twice.

## VS Project

`task_system.vcxproj` must be kept in sync manually — VS does not auto-discover files. Whenever you create a new `.cpp` or `.h` file, add it to the appropriate `<ItemGroup>` in `task_system.vcxproj`: `<ClCompile>` for `.cpp`, `<ClInclude>` for `.h` (use the path including subfolder, e.g. `src\foo.cpp`, `include\ts\foo.h`, `include\ts\detail\foo.h`).

Layout: public headers in `include/ts/`, internal (reachable-but-undocumented) headers in `include/ts/detail/`, all implementation `.cpp` (plus the `main.cpp` driver and the dev-only `mem_profile.cpp`) in `src/`; tests in `tests/`, benchmarks in `benchmarks/`, sample in `sample/`, profiling/visualization/dev tooling headers in `tools/` (header-only: `dot_writer.h`, `graph_trace.h`, `graph_introspect.h`, `trace_stamps.h`, `mem_profile.h`; `static_task_graph.cpp` consumes them via ONE unconditional include of `graph_introspect.h` — all `TS_PROFILING` gating and null checks live inside the tools headers, which stub to no-ops when it is 0). The x64 configs set `AdditionalIncludeDirectories` to `include` + `tests` + `benchmarks` + `sample` + `tools`. Includes of library headers are always **`ts/`-prefixed** — `#include "ts/guarded.h"`, `#include "ts/detail/journal.h"` — even from inside `include/ts/` headers themselves (the bare form would resolve via the compiler's current-directory rule and reintroduce path ambiguity). Local headers within `tests/`/`sample/`/`benchmarks/`/`src/` stay relative (`#include "harness.h"`, `#include "mem_profile.h"`).

Tests use the harness in `tests/harness.h`: `TS_CHECK(cond)` (non-fatal, prints a stacktrace on failure), `run(name, fn)`, `summary()`. Each group lives in its own `tests/<group>_tests.{h,cpp}` with a `run_<group>_tests()` entry, wired into `run_all_tests()` in `tests/tests.cpp`. Fatal paths are exercised via subprocess death tests (`ts::test::expect_death("<scenario>")` + a case in `run_death_scenario`).

`main` takes isolation/stress args (no arg = run everything): `--tests` (suite only, returns the failure count as exit code), `--bench` (benchmarks only), `--stress` (sample only, many frames at a fast scale — dense workload for sanitizers), `--death <scenario>` (internal, the death-test child). These exist to localize flaky failures: run one component in a loop, categorizing exit codes (1 = a `TS_CHECK` failure via `summary()`; `0xC0000005` = an actual access violation), and build with `/p:EnableASAN=true` to get the faulting stack rather than guessing.

- **Stream failures from long verification loops — don't wait for a final total.** A repeat loop should surface a hang/failure the instant it happens so investigation can start while the rest of the loop runs. Use the streaming pattern (emit one line per hang/failure; a final "done" line) rather than one summary at the end — e.g. a loop that runs each config under a per-run timeout and echoes only on `timeout`/non-zero-exit/`ASan`/`N failures`. Note: `Start-Process`'s `$p.ExitCode` reads `$null` on success in this setup (a known quirk) — check the real exit via direct invocation + the `"N failures"` line, not `Start-Process`'s exit code, or the loop will report false failures.

On Windows, ASan (`/p:EnableASAN=true`) + stress loops are the fallback (they catch memory bugs/UAF, not pure data races).
- Code style:
  - Type names are `Snake_case`: capitalized first letter, underscores between words — `Static_task_graph`, `Access_context`, `Guarded`, `Task`. This applies to all types including class templates (`Task<R>`, not `task<R>`).
  - `snake_case` for members/locals/functions; trailing `_` for private members.
  - **Acronyms/initialisms stay ALL-CAPS inside any identifier**: `write_DOT_dump`, `write_SVG`, `dur_P50`, `DOT_path`; a type starting with one is all-caps too (`DOT_writer`). Ordinary contractions are not acronyms and stay lowercase (`nav`, `xf`, `dur`, `min`), as do unit suffixes (`_us`, `_ms`). File names remain lower snake_case regardless (`dot_writer.h`).
  - Allman braces (opening `{` always on its own line, including namespaces, class/struct declarations, and lambdas):
    ```
    auto lambda = []()
    {
    };
    ```
    Short lambdas may stay one-liners (`[](int x){ return x + 1; }`); use Allman only when the body spans multiple lines.
  - Never align code or comments with padding spaces (no aligning `=`, parameters, trailing args/comments, or braces across lines). Single space only.
  - In comments, wrap references to code identifiers (type, function, variable, member names) in backticks: `Guarded`, `pipe_enqueue`, `current_access`.
  - Comment tone: technical, concise, precise — never sensational. No all-caps emphasis (write "the whole schedule is derived", not "the ENTIRE schedule"; use *italics*-free plain phrasing — if a word needs stress, restructure the sentence so it doesn't). No exclamation marks, no marketing adjectives ("blazing", "powerful"), no meta-commentary about the repo or file structure (a comment explains the code and its contracts, not how the sample is packaged). State facts and invariants; let the content carry the weight.
