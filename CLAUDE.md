# Task System

## Project

Open-source C++ task/scheduler system, generic but game-engine-focused. Inspired by Unreal Engine's Tasks System (which the author designed and implemented at Epic Games), with improvements and additional functionality. Goals: UX, performance, rich functionality.

## Author

Experienced engine programmer. Designed and implemented UE Tasks System at Epic Games. Expects expert-level C++ discussion — no hand-holding, no over-explaining idioms.

## Stack

- C++23 (MSVC/clang-cl on Windows, Visual Studio solution)
- No external dependencies
- Lock-free/low-contention concurrency preferred

## Current State

Four layers, all built and tested (**~625 checks** in Release; the harness suite, the sample, and the benchmarks all pass; TSan clean; **Shipping green** — ~479 checks, 0 failures, some skipped as not applicable, and a CI job now runs it, so the claim stays true). Sources: public headers in `include/ts/`, internal headers in `include/ts/detail/`, implementation in `src/`, plus `tests/`, `benchmarks/`, `sample/`.

Two transformations landed in 2026-08 and define the current shape: the **evolved pipe** (`docs/pipe-rebase.md` §0 — one mutex per pipe with rebuilt internals, embedded links, pipe turns as prerequisites, a unified multi-object cascade, always-on `writer_owner`, one auto-dispatching `Deferred::commit()`) and **coroutine-first** (`docs/coroutine-first.md` — the static graph keeps high-level parallelization, everything dynamic composes with `co_await`; `then`/`when_all`/the task builder/`after`/retraction/reuse are deleted, coroutines are mandatory, `sync()` is boundary-only).

- **`ts::Scheduler`** (`scheduler.{h,cpp}`, `worker_thread.{h,cpp}`; the whole scheduler layer — `Scheduler`, `Scheduler_config`, `Idle_policy`, `Priority`, `current_scheduler`/`current_worker_index`, and the queue/deque/eventcount internals — lives in `ts::`/`ts::detail` like the rest of the library) — priority queue + `std::jthread` worker pool. **Single global instance (2026-07)**: exactly ONE process-wide scheduler, `global_scheduler()` (renamed from `default_scheduler`; reconfigurable holder in `guarded.cpp` — `unique_ptr` in a namespace static + a lock-free `g_fast` read cache, mutex-guarded lazy-init/swap). Reconfigure by teardown+recreate: `configure_scheduler(Scheduler_config)` joins the current workers and builds a new pool; `Scheduler_scope` (RAII, `scheduler.h`) reconfigures for a scope and restores on exit — the way to run a block on a specific pool (samples' variant traces use it). NOT thread-safe against concurrent use — a coarse lifecycle op for quiescent points. `graph.execute()` / `ts::launch` / `async` all use the global; `execute()` dropped its `Scheduler&` param. **Follow-up (not yet done):** the public `Scheduler` ctor is still constructible (tests/benchmarks/tsan still make ad-hoc instances to unit-test the object) — fully forbidding ad-hoc PUBLIC construction needs a `detail::make_scheduler` factory (Scheduler is non-movable) so the scheduler's own unit tests keep construction access; see the single-global follow-up. `Priority {high, normal, low}` (in `priority.h`, shared with the task core) orders the queue; every queued task route threads a priority to `submit`: `ts::launch(fn, {.priority=p})`, `Guarded::async(fn, {.priority=p})`, `Graph_node::priority(p)` — stored on the block, applied at dispatch (incl. pipe-turn-gated). `parallel_for`/`async_parallel_for` helpers inherit the calling task's priority by default (`current_task->flags.priority`, resolved once on the calling thread; `Priority::normal` outside a task) — `Parallel_options{.priority}` overrides; the participating caller runs inline regardless. `parallel_for`/`async_parallel_for` fan their helpers out on the CURRENT scheduler (`current_scheduler ? *current_scheduler : global_scheduler()`, `detail::current_or_global_scheduler`), not the global default — so a `parallel_for` inside a graph node running on a dedicated scheduler uses THAT pool (the ambient-scheduler direction, TODO 3.1); previously the slices leaked to the default pool, splitting a frame's work across two pools and breaking per-scheduler tracing. Per-instance `Idle_policy` via `Scheduler_config` at construction (runtime enum, no measurable hot-path cost), three modes: `spin` = never park, yield-loop (producers never signal); `spin_then_block` (**default**, UE-style) = spin `spin_cycles` scans on the `Event_count` (eventcount, not a semaphore) before parking, producer wakes one per submit (`spin_cycles == 0` degenerates to park-immediately); `handoff` = Go-style spinner handoff (a spinner that finds work promotes a successor before running; producer issues the wake syscall only on the fully-parked 0→1 transition, else a cheap epoch bump — moves wake cost off the producer). Wake latency ~40% lower than a bare park; throughput cost on uncontended streams. See `signal_submit`/`handoff_wait` in `scheduler.cpp`. **Worker-less mode** (`Scheduler_config{.single_threaded = true}`, 2026-07, UE's no-multithreading shape): zero workers; every `submit` executes inline on the submitting thread via a bounded FIFO trampoline (per-thread pending + shared head, reentrant); blocking waits drain pending entries before parking (`detail::drain_serial_pending`, task.h→scheduler.cpp seam); priorities/idle policy inert; deterministic — serves debugging/bisection, deterministic tests, thread-less platforms, low-end fallback. Enabler: pipe turn firing happens AFTER `pipe.mutex` unlock (`collect_admissions` gathers the granted links under the lock, `fire_granted` fires them after) — inline-at-submit would deadlock releasing a pipe under its own held mutex. Worker-less graph runs skip the trace fold. Runtime, not templated — the `thread_local Scheduler* current_scheduler` rules out templating `Scheduler`. **Queues (M2)**: one lock-free MPMC queue per priority (`high`/`low` global-only; the `normal` MPMC doubles as overflow + injector for external submits) plus a per-worker Chase-Lev deque for `normal` (own submits LIFO on the producer fast path, thieves steal FIFO) — replaced the old single mutex-guarded `std::priority_queue` that was the scaling bottleneck. **Busy counters (`TS_PROFILING`)**: per-worker padded `Busy_slot` (completed `ticks` + in-flight `started` — the in-flight part matters: a trace's fold runs INSIDE the settling worker's task, so completed-only counting reads 0 on a 1-worker scheduler); `run_task` times each task ONLY while armed (`arm_busy_tracking` refcount, armed by a traced run's window — disarmed cost is one relaxed load+branch, unmeasurable on the spin throughput series; armed = 2 clock reads/task); `busy_ticks()` = relaxed sum + in-flight elapsed, feeds the trace's core-utilization headline; a per-worker `tasks` counter on the same armed path (`task_count()` = relaxed sum) feeds the trace's task-volume stat (total + mean/run: every task kind, so it far exceeds the node count — game_frame ~135/run baseline, ~153/run optimised). **Time-bucketed utilization**: per-worker `Bucket_row` (padded array of `util_bucket_count`=128 relaxed atomics); `arm_busy_tracking(origin, bucket_width)` sets the window frame + clears rows, `run_task` distributes each armed task's [start,end] busy span across the buckets it spans, `read_bucket_busy` sums per-worker at the fold (published by the run's completion barrier). Bucket width = the trace's prior-makespan estimate / 128 (fixed once; run 1 un-bucketed). Feeds the trace's true per-time utilization background (replaces the old node-concurrency proxy that undercounted `parallel_for`). **Owner attribution (per-node true busy)**: `detail::trace_owner.h` (scheduler-free seam included by `task.h`) — a `current_trace_owner` TLS set by a node body (`Trace_owner_scope` in `run_graph_node`) and inherited by launched sub-work (the `parallel_for` helper's snapshot + a coroutine frame's promise), `Trace_busy_scope` measures each body while armed and routes its span through a bridge (`trace_owner_add`/`trace_owner_armed`, defined+installed in `scheduler.cpp` → `Scheduler::add_owner_busy`) to a per-node `owner_busy_` sink (armed alongside the bucket rows, relaxed, read at fold); so a node's true-busy = body + slices + async fan-out (a `parallel_for` node reads ≫ its wall-time bar). Depends on the `parallel_for`-on-current-scheduler routing above (else the fan-out escapes the armed sink). **Task-system cost (body/machinery split, `TS_PROFILING`)**: two more per-worker `Busy_slot` accumulators, `body` (B) and `machinery` (M), both single-writer (the owning worker), relaxed, begin/end-delta'd per run by the fold — headline **overhead = M/(B+M)** (bands `overhead_ok_share` 0.05 / `overhead_bad_share` 0.15 in `graph_trace.h`) + a `body … µs / machinery … µs per run` stats line. Booking: `run_task` books its whole span to M; the functor's `Trace_busy_scope` nets its own span M→B (`trace_body_add` bridge → `add_body_ticks`), so net per-task M = setup + completion + successor dispatch. Only a SUCCESSFUL `find_work` counts (`find_work_dispatch` in the worker loop times a hit → `add_dispatch_ticks`; a failed scan is idle, not cost). A submit issued from INSIDE a functor (`parallel_for` fan-out) reclassifies B→M (`Submit_cost_scope` in `submit`, gated on the `current_in_functor` TLS → `add_submit_ticks`). Two load-bearing subtleties: (1) an INLINE body (an `access` fast path, a `set_inline` node) runs the functor bracket but bypasses `run_task`, so it must credit B only — a `trace_body_under_run_task` TLS (set by `run_task`, captured-and-cleared per body scope so a nested inline body reads false) routes it to `trace_body_only`/`add_body_only` instead of netting a nonexistent span out of M; without it M goes NEGATIVE. (2) `machinery_ticks()` needs the SAME in-flight compensation as `busy_ticks()` (add each in-flight slot's `now - started`): the fold runs inside the settling worker's terminal task, after that body netted its span out of M but before `run_task` books it back — a plain sum reads low by the whole settling body (drove M to −180 µs/run before the fix). All gated + armed-only (disarmed = one relaxed load+branch; bench held ~194 ns/op). game_frame (6-worker trace): baseline 11.1% overhead (B 39.0 ms / M 4.85 ms), optimised 6.0% (B 38.8 / M 2.48) — the metric discriminates coarser batching; upper bound (traced clock brackets + real-node acquire/handoff/dispatch, not comparable to the ~200 ns bare-bench floor). See `docs/profiler-guided-optimization.md`.
- **`Guarded<T>`** (`guarded.{h,cpp}`) — the access-controlled wrapper; the only sanctioned way to touch a thread-unsafe `T` across threads. Two verbs run `fn(T&)` (write) or `fn(const T&)` (read) on a per-object **reader/writer pipe** (concurrent readers, exclusive writer, FIFO, completion-driven dispatch), mode deduced from the functor's parameter const-ness. Both are EAGER and return a `Task<R>` (awaitable from a coroutine, `sync()`-able only from outside a task); they differ in dispatch, not in color: **`access(fn, opts={})`** is opportunistic — it runs the body **synchronously on the calling thread** when the pipe is immediately free (`pipe_try_inline` — reader joins as a reader, writer exclusive; never jumps queued work) or when the calling task already holds this pipe's write grant (`Pipe::writer_owner == current_task` — the reentrant arm, runs under the held grant with no pipe interaction), else enqueues; **`async(fn, opts={})`** always enqueues (for heavy functors). Options are an `Access_options` aggregate (`{.token, .priority}`, in `task.h`); there is no `run_inline` knob on an access verb, and with the task builder gone `Access_options` and `Launch_options` are the only two aggregates. Constructs `T` in place; adopting an existing instance is future work. The **awaitable held-grant** form is separate: `auto g = co_await ts::read_write(obj);` / `ts::read_only(obj)` yields a `detail::Pipe_guard<T, Mode>` (non-copyable AND non-movable — its address is the installed `current_access`) holding the grant for the guard's lifetime; `co_await`ing anything while a guard is live is fatal (`pipe_guard_depth`). **Multi-object**: the free functions `ts::access(fn, objs...)` / `ts::async(fn, objs...)` (options first: `ts::async({.priority=p}, fn, objs...)`) run `fn(*obj1, *obj2, ...)` over several `Guarded`s at once — per-arg mode from const-ness (`Function_traits`), the block carrying one embedded `Pipe_link` per object and entering them in **canonical (pipe-address) order** through the sequential cascade (`async_build_modes` dedups write-wins, sorts by pipe address, seeds `num_locks`, then `pipe_enter_first`); each admitted turn releases one lock and enters the next link, and the last dispatches the body under an `Access_context` declaring all. Deadlock-free by the globally canonical order — the SAME cascade graph nodes use, so nodes and multi-object accesses cannot deadlock against each other. Multi-object `access` behaves like `async` for now (the multi-object inline fast path is a follow-up). **Access-mode deduction, one spelling rule everywhere (A3+A4, 2026-07)**: non-generic functors are introspected (`Function_traits`; by-value / `T&&` resource params are `static_assert`-rejected — a copy silently discards writes); **generic lambdas deduce too**, via the rvalue-bindability probe (`detail::probed_mode` — `const auto&`/`auto&&` binds an rvalue → read, `auto&` cannot → write), so `[](const auto& p, auto& a)` works bare, no tags. Every READ position (deduced/probed/tagged) invokes the body with `const T&` (`detail::mode_ref`), so mutating under a read classification is a compile error. Constraint/return-type ORDER is load-bearing: the mode gate (`accessor_mode`, `Accessor_result`) is evaluated before any invocability probe against `const T&`, because probing a generic lambda deduces its return type → instantiates the body → hard error for a mutating body (not SFINAE); the mode-first pair is factored as `detail::Read_only_accessor`/`Read_write_accessor` (one spelling — `Guarded`'s four verbs and `Versioned::read`, which previously carried a bare pre-hardening `Async_accessor` tier that re-opened the trap), so misuse rejects as constraints-not-satisfied at the user's call site. Residual: generic `auto` by-value probes as a read and copies — undetectable, documented. `ts::as_read_only(g)`/`as_read_write(g)` tags (`detail::Access_arg<T, M>`) remain as explicit style, the `auto&&`-that-writes escape, and legal write-over-declaration; all args tagged or none (mixing is a `static_assert`); applies to `ts::access`/`ts::async` and graph `add_node`. One unified builder per surface: `async_build_modes` / `fill_node_modes` (deduced/probed/tagged tiers).
- **The pipe** (`detail::Pipe` in `guarded.h`, `detail::Pipe_link` in `detail/pipe_link.h`, implementation in `guarded.cpp`) — the per-object reader/writer serializer, rebuilt 2026-08 (`docs/pipe-rebase.md` §0; the lock-free tail chain was implemented, stress-tested and RETIRED on its own perf gate — 22 producers on one pipe measured 798 ns/op vs ~1050 uncontended, so the mutex was never the bottleneck, while every reader-group protocol piece burned). Shape: one `std::mutex`, an intrusive FIFO of **embedded** `Pipe_link`s (`queue_head`/`queue_tail`; no `Job`, no `std::deque`, no per-entry closures), `active_readers`/`writer_active`, a `condition_variable idle` for the teardown drain, and an always-on `std::atomic<Task_control_block*> writer_owner` (identity only, never dereferenced — it is what `Deferred::commit` and `Guarded::access`'s reentrant arm key off, so it cannot live behind `TS_SAFETY_CHECKS`). A `Pipe_link` is `{next, owner, pipe, index, mode}`; a null `owner` marks a HOLD entry (`pipe_acquire`'s node — the one allocating pipe path). **Pipe turns are `num_locks` prerequisites**: a task seeds `num_locks` with its `pipe_count`, `pipe_enter_first` enters link 0, and each admitted turn fires `release(owner)` which enters the NEXT link — the sequential canonical (pipe-address-ordered) cascade — with the last release dispatching through `dispatch_ready` (priority, inline, cancellation, worker-less all uniform). ONE cascade serves dynamic multi-object `async` AND graph nodes, which deleted `Multi_async_state`, its `std::map`, the `on_acquired` closures, the graph's `acquire_next` pipe walk, `preheld`/`handoff_target`, and the explicit graph write handoff. Admission collects granted links under the mutex (`collect_admissions`) and fires them after unlock (`fire_granted`) — firing under the lock would self-deadlock in worker-less mode. The drain notify is done UNDER the mutex, which makes it structurally immune to the UE `FPipe` teardown UAF (that race is a lock-free-notify artifact; `fire_granted` also never binds `Pipe&`, so nothing touches a pipe a waiter may have freed).
- **`Task<R>`** (`task.h`) — the ONE completion primitive, for every result-bearing producer (`access`/`async`/`launch`/`execute`/a coroutine): `is_done()`, `is_cancelled()`, `sync()` (blocking, returns `const R&`, non-consuming, any number of readers), `take()` (blocking, moves the result out — the single destructive consume). **The blue boundary**: `sync()`/`take()` are legal ONLY outside a task; inside one (`current_task != nullptr`, target unsettled) they are **fatal** under `TS_SAFETY_CHECKS` (`blocking_sync_diagnose`, seam task.h→guarded.cpp — a sharp same-object message when the target is an access on an object the current context holds, a general never-park message otherwise). Inside a task the verb is `co_await`. The one exemption is `parallel_for`'s internal join, which waits on group state directly and never enters `sync_wait`. `Task` is a completion handle only — it does not carry graph identity (see `Graph_node`). The shared state is a **fully monomorphic** `detail::Task_control_block` (**248 B**; not templated at all — the result is erased behind `void* result_ptr` and composed via a `Result_block<R>` wrapper the handle aliases; no `<void>` specialization; no virtual dispatch). The size fell 320→280 as retraction deletions dropped the `prerequisites` vector, 280→264 when `successors` collapsed to the single `nested_parent` slot, and 264→248 when the generation/reuse substrate was retired (`dispatch_arg` deleted, `run_state` reduced to the one-byte `body_claimed`). The **body** lives in the block too: `async`/`ts::launch(fn)` store it in an `Executable<Body,R>` wrapper reached via a `core.execute` fn-ptr; a coroutine's block is the promise's first member (frame/block fusion, one allocation). **The lock-counter** (`num_locks` + the single `nested_parent` slot) is what everything gates on: below `execution_flag` it counts unmet obligations (pipe turns), above it counts a pending `add_nested` completion (a coroutine node's frame / a nested graph run); `release()` has three thresholds — `0` → `dispatch_ready`, `execution_flag` → complete, `== pipe_count` → `pipe_enter_first` (the pipe cascade trigger). `detail::submit_ready` bridges the counter to the scheduler. **Launch verb**: `ts::launch(fn, Launch_options{.token, .priority})` is the one bare-task verb — free-running (nothing joins it — the cross-frame form), inherits no grant (a detached child's window can close while it runs). Fan out over a holder's data with `ts::parallel_for` (grant-inheriting helpers, synchronous join). The `ts::nested`/`ts::Task_scope`/`ts::join_nested` scoped-launch verbs were **removed (2026-08)** as an unsafe concurrent grant-inheriting child (rationale in `docs/coroutine-first.md` §4.3); only `detail::add_nested` survives as graph-internal completion-gating. **`Signal`** is a bodyless `Task<void>` completed by hand via `trigger()` (idempotent) with `reset()` for re-arming — the done-signal / barrier / phase gate (UE's `FTaskEvent`), and the sanctioned bridge for OS/GPU completions into `co_await`. **Cancellation**: `Cancellation_source`/`token` (cooperative); every verb takes an optional token; not-yet-started work is skipped and cancellation propagates as a completion state (`Task::is_cancelled()`); awaiting or `sync()`ing a cancelled VALUE task is fatal (check first), a cancelled `void` one resumes/unblocks normally. The two cancellation-tolerant consumes branch instead of fatalling: `try_take()` (never blocks — empty when unsettled OR cancelled, so it is also legal inside a task) and `as_optional()` (`co_await t.as_optional()` waits, then yields empty on cancellation); both move the result out, like `take()`, and neither exists for `void`. **Body-level early-out (opt-in)**: any body declaring a trailing `Cancellation_token` parameter receives the block's token (forwarded by `Executable::run`) so it can poll `is_cancel_requested()` and early-out for cancellation arriving *mid-run* — a cooperative return settles the task **completed**, not cancelled. **Push notification**: `Cancel_callback(token, fn)` (RAII, `std::stop_callback`-style) — `request_cancel()` fires registered callbacks synchronously, for work that blocks rather than polls; source/token/callback share a `detail::Cancel_state`. **Deleted by the coroutine-first transformation (2026-08)**: `then`, `when_all`, the `ts::task` builder and `after`/`add_prerequisite`, retraction (deep and shallow) with its claim/generation machinery, executable-task reuse, and the dynamic `run_inline` surface — every one is now a compile error, with `co_await` as the replacement. `dispatch_ready`/`inline_pending` survive but are graph-internal (`Graph_node::set_inline`). See `docs/coroutine-first.md` and `docs/task-internals.md`.
- **Coroutines** (`coroutine_support.h`) — mandatory, not an option: the dynamic composition vocabulary. Tasks are **eager** (`initial_suspend = suspend_never`), so a body runs on the caller's thread until its first real suspension and awaiting a settled task never suspends. `Task_promise<R>` carries `Task_control_block core` as its FIRST member (the block pointer doubles as the promise pointer; the block's `destroy` thunk destroys the frame — **one allocation** for frame + block + result), plus the creator's `Access_context` snapshot, the saved `current_task`, and the frame's **implicit scope** (`scope_children_`). `enter_segment`/`exit_segment` swap `current_task` + `current_scope_children` around every segment, so a resumed segment on another worker sees the same grants. `final_suspend` drops the body self-lock, so a frame completes only after any `add_nested` child (a nested graph run) settles. Awaiters: `Task_awaiter<R>` (`await_ready` = settled), `Pipe_guard_awaiter<T,Mode>` (the held-grant guards; names the coroutine's own block as `writer_owner`, so `Deferred::commit` inside the guard takes the inline arm). Each uses a two-state `exchange` handshake between the completion callback and the suspend tail so the second one to arrive owns the resume. Resumption goes through a bounded thread-local **resume trampoline** (`resume_pending`/`schedule_resume`, iterative so the stack stays O(1), type-erased so no per-resume allocation) — the eager-task equivalent of symmetric transfer: the settling/granting thread resumes the frame with no queue hop. `pipe_guard_depth` doubles as the suspension-under-guard detector (`co_await` under a live guard is fatal).
- **`Static_task_graph`** (`static_task_graph.{h,cpp}`) — build-once / run-many DAG. **Node naming + structure dump**: `add_node` takes a leading `ts::Named` (the one unified debug-identity type, `named.h` — implicit from a static literal, `add_node("physics", fn, objs...)`; `add_node({}, fn, objs...)` captures the `add_node` call site via `std::source_location`, labeling `file:line`; a defaulted param after the object pack is not expressible in C++, hence the leading position, UE-style); names are kept when `TS_DEBUG_NAMES` is on (default under the harness and forced on by `TS_SUSPENSION_REGISTRY`). `compile(DOT_path)` (default null) writes the compiled DAG as Graphviz DOT via the header-only `tools/dot_writer.h` (`ts::tools::DOT_writer`), dark monokai-derived theme: green edges (`#a6e22e`), line style = provenance — solid (penwidth 2.0) = explicit `after`/`before`, dashed (penwidth 1.8) = conflict-derived — with the object+modes as SVG hover tooltip (`obj3: RW->RO`); an edge that is both renders explicit-styled with the conflict tooltip; unnamed un-sited nodes label `node<N>`. Objects are named via `ts::Named` — a **required** leading ctor arg on `Guarded`/`Versioned` (the ONLY constructor takes a leading `Named` — a literal or `ts::Named{}` for the construction site; a distinct wrapper constrained to `same_as<Named>` so it can't be mistaken for `T`'s first ctor arg, `Guarded<std::string> g{"hello"}` fails to compile; stored as `Pipe::debug_name`, kept when `TS_DEBUG_NAMES`) — so derived-edge tooltips read `physics: RW->RO`; unnamed sites fall back to `file:line` or `objN` ordinals. A second ctor `Guarded(Named, Rank, args...)` declares the object's lock rank (`ts::Rank`), required only for objects DYNAMICALLY AWAITED while another grant is held. **Runtime trace (aggregated, no samples)**: `set_trace(tools::Graph_trace*)` (requires compile(); nullptr detaches; forward-declared in the public header, only the .cpp includes `tools/graph_trace.h`) — the graph's whole involvement is a cpp-local `Trace_stamps` class (pre-sized arrays; `steady_clock` ticks — ready at the dep-counter zero transition, start/end around the body — + worker index, armed per run only when attached; every method a no-op under `TS_PROFILING=0`, so the run logic carries no `#if`s) with 4 mark calls and ONE `stamps.fold` call at run settle (settling thread, before `done` settles so a sync()ed caller reads a consistent trace; cancelled runs skipped; recompile re-pushes structure and resets aggregates). `Graph_trace` (header-only, `tools/graph_trace.h`) streams per node Welford mean/var + P² P50/P95 + min/max + per-worker histogram + dispatch wait (ready→start = acquire+queue latency) + critical-chain counter, per edge the mean meet point `(end_u+start_v)/2` + a chain counter, global makespan + critical work — O(nodes+edges) state. **Measured critical path**: per run, a backward walk from the latest-finishing node through the binding predecessor (latest-end in-edge) counts chain membership; aggregate = criticality FREQUENCY (no single path across variable runs), rendered as a colour blend by share — node border+label cyan→orange, edge green→pink (dash keeps carrying provenance; widths uniform) — with legend rows. A CPM pass (median durations, zero latency) at `write_SVG` yields per-node slack (structural bound; divergence from the measured chain = scheduling-bound, not dependency-bound). Grant-inheriting fan-out over the node's owned data is `ts::parallel_for` (its helpers snapshot the node's `Access_context` by value and join synchronously, so they stay inside the node's grant window) — the `ts::nested`/`Task_scope` scoped-launch verbs that once did this were **removed (2026-08)** as an unsafe concurrent grant-inheriting child (see `docs/coroutine-first.md` §4.3). **Coroutine node bodies (2026-08)**: a body returning `ts::Task<void>` is detected at `add_node` (`fill_node_modes` inspects the invoke result) and its frame is attached via `detail::add_nested`, so the node completes when the FRAME completes, not at the body's first suspension — grants are held across suspensions. `detail::add_nested` (the internal completion-gating mechanism, kept) also gates a nested graph run; the frame's implicit-scope TLS (`current_scope_children`/`scope_children_`) is retained solely so the non-quiet-scope lending check can see a still-running nested run — no longer user-reachable. Access modes deduce from the coroutine's parameters exactly as for functor nodes; functor nodes stay the zero-frame common case. **Lifetime fatals (2026-07, `TS_SAFETY_CHECKS`)**: destroying/move-assigning-over a graph (or recompiling) while a run is in flight is fatal; `compile()` registers the graph on each pipe (`Pipe::graph_refs`, field and all code compiled out with the harness) and `~Guarded` fatals while a compiled graph still references the object. Node blocks + the `Run_state` are built at `compile()` and re-armed per run (nodes dispatch via the raw scheduler API; completion via the block's persistent `on_complete` fn-ptr, not a per-run continuation), so a run allocates only its `done` handle — re-runs are essentially allocation-free (~19% faster than per-run blocks). The graph is movable (`execute()` refreshes the blocks' back-pointers); runs are sequential (one at a time). Nodes access their objects **directly** (bypassing per-call dispatch), so each node takes a pipe turn on every object it touches before running and releases at completion — a concurrent `Guarded::async` on the same object queues behind the node that holds it instead of racing it (the harness does *not* catch that race — both sides declare access). Since the pipe rebase this is the SAME cascade as multi-object `async`: each node's `Pipe_link`s live in a contiguous `compile()`-time slab (`node_links_`), bound in ascending pipe-address order and re-armed per run, and the node's cascade starts at data-ready. An object is held only over each accessor's `[first turn, completion]` window — free in the gaps for async, and a **reader** node holds it as a reader so a concurrent async read (or another reader node) overlaps; a **writer** node is exclusive. The explicit object handoff (`preheld`/`handoff_target`) is GONE with the rebase — its optimization survives only opportunistically, when a successor's link is already queued at the predecessor's release, so release + next admission happen in one mutex pass. **Inline dispatch** (`Graph_node::set_inline()`) survives: a ready node runs on the thread that settled its last prerequisite via the shared `dispatch_ready` trampoline. **Nested graph runs (2026-08, `docs/coroutine-first.md` §4.8)**: `co_await inner.execute()` from a node works via the LEND protocol — `bind_links_for_run` intersects the inner graph's compiled access set with the caller's `Access_context` at every `execute()` and re-binds the `compile()`-time link slab to only the objects the run must take turns on, so a lent object's turn is simply never taken (an awaited inner run is contained in the caller's grant window, which is already the exclusion it needs; without this the inner node queues behind the grant its suspended caller holds — deadlock). Inner conflict edges still order inner nodes among themselves on a lent object, and the pipe never sees the lend (external `async`s queue behind the caller's hold as before). Recursion composes by construction. A nested run also JOINS the caller's implicit scope by default, so an un-awaited inner run cannot float; `execute({.detach = true})` opts out of both (a detached run is not contained, so it gets no lend and queues like external work). Three fatals (`TS_SAFETY_CHECKS`), each with a companion test: a caller holding READ where the inner graph writes; lending while an earlier un-awaited nested run of the caller is still in flight; and `execute()` while a run of that graph is in flight — the last closing a previously unguarded `Run_state` corruption. One run per graph instance remains the rule (TODO 2.3 is the relaxation). **Concurrent runs of DIFFERENT graphs over shared objects are supported** (validated 2026-08): canonical pipe-address ordering makes a cross-graph wait cycle impossible and the pipe serializes their conflicting nodes as it would a node against an async — safe, but cross-graph ORDERING is nondeterministic, so don't build semantics on it. See `docs/task-internals.md` §10 for the per-node turn mechanism + the one scenario with no structural fix (incomplete declarations — the completeness hazard by definition).
- **`Deferred<T>` / `Versioned<T>`** (`journal.h` + `deferred.h` + `versioned.h`, header-only; `journal.h` holds the shared staging machinery — `detail::Journal`, `Recorder`, `Parallel_recorder`) — the deferred-write layer from `docs/command-buffer-design.md` (design 4, implemented; vocabulary: **stage / commit / publish**). `Deferred<T>` binds to a `Guarded<T>`: `recorder()` mints move-only producer handles whose `stage(closure)` appends to private per-recorder storage (**no grant on the target**, contention-free between recorders — `detail::Journal<T>`, shared machinery); **ONE commit verb** (unified 2026-08, `commit_async` removed): `commit(opts)` auto-dispatches on grant ownership — (1) `pipe.writer_owner == current_task` (a graph node's declared write, an `access`/`async` write body, a coroutine `read_write` guard) applies INLINE under that grant and returns a pre-settled sentinel (one shared static block, no allocation; it provides no happens-before edge — observers order through the object's pipe); (2) sub-work running under a parent's INHERITED grant is not the holder, so its commit would enqueue behind the very grant it waits out — fatal under `TS_SAFETY_CHECKS` (`holds_write_epoch`), call `commit()` from the grant-holding task; (3) anyone else enqueues an ordinary async write and returns its task. The dtor's in-flight check keys off the **enqueue-and-record seam**: the enqueue stores the new write's block into `last_commit_` while still under the pipe's mutex, which is what made the old external `commit_mutex_` deletable (a plain post-enqueue store could lag FIFO order and let the settled-check miss a pending write). Apply order is deterministic: recorder-creation order, FIFO within — independent of thread timing. Producer→commit ordering is hand-wired (graph edges); `Access::append` edge derivation is deliberately deferred. `Versioned<T>` = journal + two replicas behind one `Guarded` front (readers declare ordinary read on `state()`; the swap exchanges CONTENTS, so the front's address is stable — zero graph/pipe/harness changes): `read()` sees the last published version all frame (no read-your-writes — outputs arrive as the NEXT version), `publish()` is a **three-phase** step where only the swap holds the write grant — (1) cut + apply to shadow, grant-free; (2) swap, ~ns; (3) resync as a **pipe read job**, overlapping readers of the new version while FIFO holds the next writer (incl. a graph flip's acquire) behind it — the pipe is the shadow-ownership chain; consecutive publishes also chain phase 1 after the previous resync internally (an empty publish doubles as a resync fence). **Single-publisher enforcement**: a graph/inline publish catching an unresolved dynamic publish is fatal at flip entry (`TS_SAFETY_CHECKS`); a SYNCED publish before a run is deterministically legal (the swap enqueues the resync before triggering the phase gate, so the flip pipe-orders behind it), and a dynamic publish arriving mid-flip chains behind the flip. Graph form: `ts::publish_body(v)` as a node with write on `v.state()`. Resync policy per instance: `replay` (default — re-apply the batch; both applications see bit-identical pre-states, so deterministic commands give bit-identical replicas; **commands must be deterministic**), `copy` (user fn or copy-assign), `overwrite` (writer rewrites everything; no resync). `set_divergence_check(hash)` fatals on replica mismatch after replay (bitwise — replay has no FP drift on one binary). Staged-but-unapplied commands at destruction are **fatal** under `TS_SAFETY_CHECKS` (lost writes); `discard()` is the escape. `~Deferred` with an ENQUEUED commit still in flight is also fatal (await the returned task first) — the dtor snapshots the last commit's handle under the pipe mutex (`last_commit_`; FIFO makes one handle cover all commits) and is non-blocking when it has settled; shipping builds keep a conditional `wait_until_idle` as the UAF safety net (the pending job captures `this`). Selection rule: `Versioned` is for state whose per-frame delta is *data*; when producing version N+1 is heavy computation (physics sim), keep ONE instance behind `Guarded` and version its output *extract* — see `sample/physics.cpp` (sealed `Guarded<Physics_world>` with a single grant holder — the sim's write; `Deferred` inputs, `Versioned` pose snapshot, id-reservation forward refs, batch-extract idiom; deterministic across runs). Known v1 costs: closure-tier commands (`move_only_function`, per-command alloc past SBO — typed-POD/arena tier pending, alloc-audit), per-slot mutex on stage (uncontended one-producer use; exists for the dynamic stage-vs-cut race). **Parallel staging**: `parallel_recorder()` mints a per-WORKER handle (slots keyed by the scheduler's `current_worker_index` TLS + an overflow lane for non-worker threads — the `parallel_for` caller's share, inline bodies) for ONE producer parallelized internally: contention-free under any chunking (guided/stealing/long tail), but cross-thread apply order is nondeterministic — use it for per-key-single or commutative commands (or a sorted commit); index-keyed `Recorder` lanes remain the raw-determinism answer. Batch order is still fixed at the cut, so `Versioned` replay stays exact either way. **Ordering contract** (journal.h): intra-recorder FIFO is semantic — build on it; **cross-recorder order is arbitrary — never build semantics on it** (same-key cross-producer writes are a conflict; fix = one writer per key / commutative commands / future sort keys), but it IS deterministic given a deterministic mint/destroy sequence, so runs are reproducible (bugs included). Recorder dtors release their slots to a free-list (live slots bounded by peak concurrent recorders — mint/destroy per frame no longer grows the journal; staged-but-uncut commands survive release); a reused slot keeps its position — observable only to programs already violating the contract. Keeping >4096 recorders alive is fatal under `TS_SAFETY_CHECKS` (`Journal::max_slots` — catches mint-and-retain-per-frame). Recorders must not outlive their `Deferred`/`Versioned` (dtor touches the journal). **Pattern recipe — blackboard**: no new type; shared board = `Versioned<Blackboard>`, private board = plain member, key-change notification = dispatch node after the flip + per-subscriber value diff (doc §7.4; single-file sample `sample/blackboard.cpp`).
- **Access harness** (`access.{h,cpp}`) — `TS_CHECK_ACCESS()` at the top of every guarded method checks `this` against a thread-local `Access_context` the scheduler/pipe installs per task; a violation routes to `ts::fatal`. ~1 ns/call. Subtasks (e.g. `parallel_for` chunks) inherit the parent node's context. **Grant-window validity (2026-07)**: each `Pipe` carries a `write_epoch` (seqlock parity — bumped at write acquire/release under the pipe mutex, +2 on a graph write handoff; readers never bump); context entries declared under a pipe grant capture it, and `access_check` fatals with a stale-grant diagnostic when an inherited snapshot outlives its window (a non-nested `ts::launch` touching the launcher's data after the launcher's scope released — nested-gated sub-work is structurally never stale). `Access_context::check` returns granted/stale/none. Gated by `TS_SAFETY_CHECKS`.
- **Waiting-rule policy** (`rules.h`, design of record `docs/waiting-rule-policy.md`) — the coroutine-first waiting rules (`docs/coroutine-first.md` §2) are enforced by runtime checks that fatal, and each is separately (1) compiled in via `TS_ENABLED_RULES` (a bitmask of `TS_RULE_*`) and (2) opted out of per scope via `ts::Relaxed_scope` for the rules that permit it. `ts::Rule` mirrors the bits: **`in_task_sync`** (`sync()`/`take()` inside a task), **`await_under_guard`** (`co_await` while a `Pipe_guard` is live), **`access_rank`** (awaiting an object out of declared rank order), **`circular_wait`** (a held-grant → awaited-pipe wait cycle), **`deadlock_net`** (quiescence with no possible external wakeup). Rule classes: `advisory` (`in_task_sync|access_rank|circular_wait` — a scoped `Relaxed_scope` opt-out, "I uphold this by means the library can't see"), `structural` (`await_under_guard` — compile-out-only, its absence corrupts rather than merely permits, so it is the ONE rule shipping keeps), `net` (`deadlock_net` — global, unscopable). `set_default_relaxed_rules(Rule)` is a process-wide advisory-relaxation baseline. `circular_wait`/`access_rank` read grant bookkeeping that exists only under `TS_SAFETY_CHECKS`, so they can't outlive it whatever the policy asks (the EFFECTIVE mask = policy ∩ build support). `rule_enforced(rule)` is the one predicate a check calls, only AFTER the cheap hazard condition is already true (the relaxation lookup stays off the common path). A `Relaxed_scope` entered in a coroutine body follows the ambient task state, not the thread (`Relaxed_carrier` on the promise re-installs it around every segment). **`ts::Rank`** (`access.h`) — a declared lock order (`Guarded(Named, Rank, args...)`), NOT defaulted, required only for objects dynamically awaited while another grant is held; the `access_rank` rule fatals on an out-of-order await. **Deadlock report, three tiers** (`docs/waiting-rule-policy.md` §7): tiers 1 (the `circular_wait` cycle) and 2 (the `deadlock_net` quiescence net — the scheduler idle with nothing externally outstanding for `set_deadlock_net_window`, default 2 s) are free and always present; tier 3 is `TS_SUSPENSION_REGISTRY` — an opt-in per-suspension registry (who is suspended, what they await, what they hold), default ON in DEBUG only (a linked-list insert/remove per suspension, ~30 ns, ~8% on the suspend/resume microbench), which forces `TS_DEBUG_NAMES` on (a registry of block pointers is not a diagnostic). **`ts::External_wait`** (`task.h`) — the `deadlock_net` escape: hold one while a wakeup owned by a thread the scheduler doesn't run (OS I/O, GPU fence, a `Signal` from a dedicated thread, a `Frame_gate` `open()`) is outstanding, so the net doesn't false-positive; a FORGOTTEN registration produces a false deadlock report, which is why the report names the type. **`ts::Named`** (`named.h`) — the one unified debug-identity type for graph nodes (required), guarded objects (required), and tasks (optional, `Launch_options::name`/`Access_options::name` — the call SITE is captured by the verb's own defaulted `source_location`, so an unnamed task is still identified). A `Named` is a literal OR a `{}` call-site capture (`file`+`line` only, three words); `named_display` renders it. The load-bearing library rule: a defaulted `source_location` captures the CALLER, so it must sit on the OUTERMOST function the user calls and be passed down explicitly — an inner helper re-defaulting it captures the library header (`tests/named_tests.cpp` asserts captured names point into the test file). Debug identity is gated by `TS_DEBUG_NAMES` (default = the harness, forced on by `TS_SUSPENSION_REGISTRY`).
- **`fatal.{h,cpp}`** — exceptions are disabled project-wide; all non-recoverable failures call `ts::fatal` (message + `std::stacktrace` + `abort`). Tests are the one place failures are non-fatal (the harness records and continues); fatal paths are checked via subprocess death tests. **`TS_ENSURE(expr, message)` (2026-07, `TS_SAFETY_CHECKS`-gated)** — UE-`ensure`-shaped recoverable assert macro (fatal.h): evaluates `expr` once in both configs and yields its bool; on failure bumps `ts::ensure_failure_count()` on EVERY occurrence but reports ONCE PER CALL SITE (captureless-lambda function-local static claim), through a swappable presentation handler (`ts::set_ensure_handler`, `std::set_terminate` shape; default = `ENSURE FAILED:` + stack + debugger-break if attached via `detail::is_debugger_present`/`debug_break`, the C++26 P2546 pair polyfilled Win/Linux/mac; `ts::fatal` breaks too, before `abort`). ## Terminology

Use these terms precisely, in code and discussion:

- **spin waiting** — yielding in a loop until a condition holds (e.g. the worker idling on an empty queue, or a fixed-duration `spin()`). Does no other work.
- **busy waiting** — doing *unrelated* work while waiting, e.g. a thread that pops and executes other queued tasks while waiting for a specific task to complete. Usually a bad idea (stack growth, latency, priority inversion). Not the same as spin waiting.

## Design Principles & Lessons

- **Granularity decides parallelism.** Whole-object (system-level) access serializes every reader against any writer, collapsing the DAG toward sequential. Shard mutable state — the sample double-buffers transforms (`world_xf_prev` read by early systems, `world_xf` written by propagation and read by late systems, swapped per frame) so many readers don't contend with the writer. The central tension: static safety wants coarse access sets, performance wants fine ones.
- **Completeness hazard.** The graph's safety holds only if its access declarations are *complete*. A manual task or an escaped reference touching a system the graph believes it owns races — and the graph can *promote* a latent bug to a live one by manufacturing parallelism around it. The harness is the runtime oracle for undeclared access.
- **Never block inside a graph node / task — suspend instead.** An in-task `sync()`/`take()` on unsettled work is FATAL (checked builds), not merely discouraged: blocking ties up a worker and risks deadlock under worker exhaustion, and there is no retraction left to rescue it. Consuming a result inside a task means `co_await` (the frame suspends, the worker is freed, grants are held across the suspension); outside a task — the main loop, an external thread, a test — `sync()` is the sanctioned boundary verb. `parallel_for`'s join is the one structural exemption (it waits only on work that provably occupies a worker).
- **Suspension under a grant, in preference order** (`docs/coroutine-first.md` §2). Under a held grant a task may safely suspend on (a) its own spawned children (they inherit the grant, no cycle can pass through the holder's objects) and (b) the same object (reentrancy — `writer_owner == current task` runs inline under the grant). Suspending on a FOREIGN object is safe only if no waits-for cycle forms, which is a global property the caller cannot see locally — the failure mode is a suspended ABBA deadlock where no thread parks and the run silently never completes. Prefer, highest first: declare the object on the node and let `compile()` order it; a `Versioned` snapshot when last-frame data suffices; `Deferred` staging for outward writes; awaited dynamic access as the residual (short bodies, read mode). The waits-for cycle detector catches the residual case in checked builds.
- **Sync state shared across threads must outlive every participant** — heap it (`shared_ptr`), never leave it on a stack frame the initiator may unwind first. (This cost a real use-after-free in `parallel_for`: the caller returned on `completed == chunks` and unwound while a helper still touched the stack counters.)
- Prefer per-instance runtime config over templating when a `thread_local` singleton would fracture across instantiations. Prefer a counting semaphore over a condition variable for worker wake (decouples from the queue mutex; survives a future lock-free queue). Prefer intrusive / zero-alloc on hot paths; avoid virtual dispatch.
- **Prefer intrusive ref-counting over `std::shared_ptr` for types we control.** Use the generic `detail::Ref_counted<T>` (CRTP base) + `detail::Ref_ptr<T>` handle + `detail::make_ref<T>()` in `ref_count.h`: one allocation (not two), a one-pointer handle (not two words), fewer atomics. Reserve `std::shared_ptr` for interop with external types. `Task_control_block`/`Task_ptr` keep their own hand-rolled variant (it aliases inside `Result_block`/`Executable` wrappers, so it needs a `destroy` thunk rather than `delete T*`). Converted so far: `Cancel_state` (`Multi_async_state` and `when_all`'s `Join_state` were converted and then deleted outright by the pipe rebase and the coroutine-first transformation).
- **Allocation discipline (hot paths).** Never spray separate heap allocations for individual small fields — the deleted `when_all` was the cautionary case (four `make_shared` for a slots tuple, an `atomic<int>`, an `atomic<bool>`, and a `std::function`, plus two blocks = ~6 allocs/join, the worst per-op offender the library ever had). **One state struct, one allocation** (ideally the intrusive block itself); fold counters/flags/continuations in as members. The pattern is now standard here: `Piped_executable<Body,R,N>` puts block + result + body + N pipe links in one allocation, and `Task_promise<R>` puts block + result inside the coroutine frame. A per-type recycling free-list is trivial because each `Exec<Body,R>`/`Result_block<R>` instantiation is a *constant* size (variable across types, const per type). Reserve bump/linear (arena) allocation for provably scope-bounded lifetimes (a `parallel_for`, a graph run, a frame with no escaping tasks). Prefer a tunable-SBO callable over `std::move_only_function`/`std::function` (size the inline buffer to the common task-functor size so the closure never heaps), and intrusive, dependent-side links for the block's last edge vector, `continuations` (`prerequisites` is gone with retraction, and `successors` collapsed to a single `nested_parent` pointer once the audit showed its fan-out was structurally 0-or-1 — 24 B and an allocation for one pointer). See `docs/TODO.md` §4 (4.1/4.2/4.7) for the ranked plan.
- **Debugging flaky crashes**: localize with `main`'s `--tests` / `--bench` / `--stress`, categorize exit codes (1 = a `TS_CHECK` failure via `summary()`; `0xC0000005` = an access violation), and build `/p:EnableASAN=true` to get the faulting stack. Get the stack before theorizing — inspection alone misled twice.

## VS Project

`task_system.vcxproj` must be kept in sync manually — VS does not auto-discover files. Whenever you create a new `.cpp` or `.h` file, add it to the appropriate `<ItemGroup>` in `task_system.vcxproj`: `<ClCompile>` for `.cpp`, `<ClInclude>` for `.h` (use the path including subfolder, e.g. `src\foo.cpp`, `include\ts\foo.h`, `include\ts\detail\foo.h`). **AND add the same entry to `task_system.vcxproj.filters` with a `<Filter>` assignment matching its directory** (`src`, `include\ts`, `include\ts\detail`, `tests`, `tools`, `tsan`, …; declare a new `<Filter>` in the first `ItemGroup` if the directory has none yet). The `.vcxproj` controls what *builds*; the `.filters` controls the Solution Explorer tree — a file added only to `.vcxproj` compiles fine but appears ungrouped at the VS project root. A drift check: the set of `Include=` paths in the two files must be identical (they drifted once because files were added to `.vcxproj` only, landing 12 files at the root).

Layout: public headers in `include/ts/`, internal (reachable-but-undocumented) headers in `include/ts/detail/`, all implementation `.cpp` (plus the `main.cpp` driver and the dev-only `mem_profile.cpp`) in `src/`; tests in `tests/`, benchmarks in `benchmarks/`, sample in `sample/`, profiling/visualization/dev tooling headers in `tools/` (header-only: `dot_writer.h`, `graph_trace.h`, `graph_introspect.h`, `trace_stamps.h`, `mem_profile.h`; `static_task_graph.cpp` consumes them via ONE unconditional include of `graph_introspect.h` — all `TS_PROFILING` gating and null checks live inside the tools headers, which stub to no-ops when it is 0). The x64 configs set `AdditionalIncludeDirectories` to `include` + `tests` + `benchmarks` + `sample` + `tools`. Includes of library headers are always **`ts/`-prefixed** — `#include "ts/guarded.h"`, `#include "ts/detail/journal.h"` — even from inside `include/ts/` headers themselves (the bare form would resolve via the compiler's current-directory rule and reintroduce path ambiguity). Local headers within `tests/`/`sample/`/`benchmarks/`/`src/` stay relative (`#include "harness.h"`, `#include "mem_profile.h"`).

Tests use the harness in `tests/harness.h`: `TS_CHECK(cond)` (non-fatal, prints a stacktrace on failure), `run(name, fn)`, `summary()`. **Config-conditional tests use `run_if(predicate, reason, name, fn)`, never `#if` around the registration** — a test wrapped in `#if` vanishes silently, which is how the Shipping configuration accumulated six failures and a crash unnoticed; `run_if` prints `[skip] name (reason)` and `summary()` reports `N skipped (not applicable in this configuration)`. The predicates are named constants in `harness.h` (`with_harness`, `with_profiling`, `with_rule_*`). A **death** test must name the switch that compiles in the fatal it expects, not merely `with_harness`: with the fatal absent the child does not abort and usually does the thing the fatal prevented — generally a deadlock, so the parent hangs in `_spawnl(_P_WAIT)` rather than failing. Each group lives in its own `tests/<group>_tests.{h,cpp}` with a `run_<group>_tests()` entry, wired into `run_all_tests()` in `tests/tests.cpp` (currently scheduler, access, guarded, pipe, task, graph, parallel, coroutine, integration, deferred, versioned, named, rules; shared fixtures — `Rw_probe` and friends — in `tests/test_util.h`). Fatal paths are exercised via subprocess death tests (`ts::test::expect_death("<scenario>")` + a case in `run_death_scenario`).

`main` takes isolation/stress args (no arg = run everything): `--tests` (suite only, returns the failure count as exit code), `--bench` (benchmarks only), `--stress` (sample only, many frames at a fast scale — dense workload for sanitizers), `--death <scenario>` (internal, the death-test child). These exist to localize flaky failures: run one component in a loop, categorizing exit codes (1 = a `TS_CHECK` failure via `summary()`; `0xC0000005` = an actual access violation), and build with `/p:EnableASAN=true` to get the faulting stack rather than guessing.

## Session Guidance

- **Integration and publication require the author's explicit, standalone approval — never bundle them into a larger task.** These actions each need their own yes, asked as its own question at the moment of the action, not inferred from approval of a worklist or plan that happens to contain them: (1) merging or fast-forwarding a feature branch into `master`, or otherwise promoting branch work to `master`; (2) `git push` to any remote (origin is public); (3) deleting or force-moving a branch, tag, or worktree; (4) history rewrites (rebase-onto-master, force-push, filter). Committing work-in-progress to a feature branch, or to `master` when the author has directed the current work there, does not need a fresh yes — the gate is on *integration and outward publication*, not on saving progress. When a plan reaches one of these steps, STOP and ask explicitly ("ready to merge X into master?" / "push to origin?") even if the plan was approved as a whole. Rationale: the pipe/coroutine-first branch was once promoted to `master` inside an approved worklist and the author missed it; integration points must be visible decisions.
- Multiple sessions will work on different aspects — read this file for context each time
- **Public docs contract**: `docs/guide.md` (user guide — mid-level devs, MT-literate, not gamedev) and `docs/design.md` (design rationale — expert engine devs) are the two public-facing documents; **update them with every push** that changes public API, behavior, or design decisions. `README.md` is the pitch + teaser only (don't duplicate the guide). This file (CLAUDE.md) stays internal, LLM-oriented.
- Propose design options with tradeoffs before implementing non-trivial changes
- Number the sections/points of sizeable responses so the author can address particular parts by number. Same for documents: number the headings/items of reports, surveys, and design docs whenever referencing them in discussion makes sense (idea lists, option menus, findings). Numbers are stable IDs — mark items done/rejected, don't renumber (the TODO.md convention).
- Perf matters: flag any change that adds allocations or contention on hot paths
- **Offload long or open-ended work to a background agent** so the main session stays interactive: bug investigations (deadlock/heisenbug hunts, TSan/ASan triage), long test/benchmark/loop runs, and multi-file research. Launch a `fork` (inherits context) or a fresh agent, keep chatting, and fold in its findings when it reports. Reserve the main session for design discussion and the actual edits.
- **Stream failures from long verification loops — don't wait for a final total.** A repeat loop should surface a hang/failure the instant it happens so investigation can start while the rest of the loop runs. Use the streaming pattern (emit one line per hang/failure; a final "done" line) rather than one summary at the end — e.g. a loop that runs each config under a per-run timeout and echoes only on `timeout`/non-zero-exit/`ASan`/`N failures`. Note: `Start-Process`'s `$p.ExitCode` reads `$null` on success in this setup (a known quirk) — check the real exit via direct invocation + the `"N failures"` line, not `Start-Process`'s exit code, or the loop will report false failures.
- After any change to concurrent code (scheduler, the pipe, graph, `parallel_for`, the coroutine awaiters/resume trampoline), verify with ThreadSanitizer: `bash tsan/run.sh` on a Linux host (TSan has no Windows runtime — see `tsan/README.md`). On Windows, ASan (`/p:EnableASAN=true`) + stress loops are the fallback (they catch memory bugs/UAF, not pure data races).
- Code style:
  - Type names are `Snake_case`: capitalized first letter, underscores between words — `Static_task_graph`, `Access_context`, `Guarded`, `Task`. This applies to all types including class templates (`Task<R>`, not `task<R>`).
  - `snake_case` for members/locals/functions; trailing `_` for private members.
  - Avoid single-character names except in very short scopes (a loop index, a one-line lambda parameter). A variable that lives across a whole function gets a real name (`graph`, not `g`; `world`, not `w`).
  - Lines up to 120 characters (`.clang-format` `ColumnLimit: 120`). Prefer one line where it fits — don't wrap at the old 100.
  - Braces on `if`/`else`: a branch whose statement spans multiple lines is always braced; when one branch of an `if`/`else` is braced, brace both. A single-line branch with a single-line counterpart may omit braces.
  - **Acronyms/initialisms stay ALL-CAPS inside any identifier**: `write_DOT_dump`, `write_SVG`, `dur_P50`, `DOT_path`; a type starting with one is all-caps too (`DOT_writer`). Ordinary contractions are not acronyms and stay lowercase (`nav`, `xf`, `dur`, `min`), as do unit suffixes (`_us`, `_ms`). File names remain lower snake_case regardless (`dot_writer.h`).
  - Allman braces (opening `{` always on its own line, including namespaces, class/struct declarations, and lambdas):
    ```
    auto lambda = []()
    {
    };
    ```
    Short lambdas may stay one-liners (`[](int x){ return x + 1; }`); use Allman only when the body spans multiple lines.
  - Never align code or comments with padding spaces (no aligning `=`, parameters, trailing args/comments, or braces across lines). Single space only.
  - Safety-only state is FULLY gated by `TS_SAFETY_CHECKS` — fields included, not just behavior (`Pipe::write_epoch`, `Pipe::graph_refs`, `Access_context::Entry`'s epoch pair): shipping carries no dead bytes for the harness. The only unconditional exceptions are state that BEHAVIOR keys off, not just diagnostics — `Pipe::writer_owner` (`Deferred::commit`'s auto-dispatch and `access`'s reentrant arm read it in every build) — and genuinely free storage such as a spare bit in an existing packed byte. Mixed-config TUs are an ODR violation regardless of layout; the link-time tripwire in `access.h` (`detect_mismatch` on MSVC, a config-named anchor symbol elsewhere) turns that mistake into a link error.
  - In comments, wrap references to code identifiers (type, function, variable, member names) in backticks: `Guarded`, `pipe_enter_first`, `current_access`.
  - Comment tone: technical, concise, precise — never sensational. No all-caps emphasis (write "the whole schedule is derived", not "the ENTIRE schedule"; use *italics*-free plain phrasing — if a word needs stress, restructure the sentence so it doesn't). No exclamation marks, no marketing adjectives ("blazing", "powerful"), no meta-commentary about the repo or file structure (a comment explains the code and its contracts, not how the sample is packaged). State facts and invariants; let the content carry the weight.
