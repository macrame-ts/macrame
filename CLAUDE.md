# Task System

## Project

Open-source C++ task/scheduler system, generic but game-engine-focused. Inspired by Unreal Engine's Tasks System (which the author designed and implemented at Epic Games), with improvements and additional functionality. Goals: UX, performance, rich functionality.

## Author

Experienced engine programmer. Designed and implemented UE Tasks System at Epic Games. Expects expert-level C++ discussion — no hand-holding, no over-explaining idioms.

## Stack

- C++23 (MSVC/clang-cl on Windows, Visual Studio solution)
- No external dependencies
- Lock-free/low-contention concurrency preferred

## Current State

Four layers, all built and tested (in Release the harness suite, the sample, and the benchmarks all pass; TSan clean; **Shipping green** — 0 failures, some skipped as not applicable, and a CI job now runs it, so the claim stays true). Sources: public headers in `include/ts/`, internal headers in `include/ts/detail/`, implementation in `src/`, plus `tests/`, `benchmarks/`, `sample/`.

Two transformations landed in 2026-08 and define the current shape: the **evolved pipe** (`docs/pipe-rebase.md` §0 — one mutex per pipe with rebuilt internals, embedded links, pipe turns as prerequisites, a unified multi-object cascade, always-on `writer_owner`, one auto-dispatching `Deferred::commit()`) and **coroutine-first** (`docs/coroutine-first.md` — the static graph keeps high-level parallelization, everything dynamic composes with `co_await`; `then`/`when_all`/the task builder/`after`/retraction/reuse are deleted, coroutines are mandatory, `sync()` is boundary-only).

- **`ts::Scheduler`** (`scheduler.{h,cpp}`, `worker_thread.{h,cpp}`; the whole scheduler layer — `Scheduler`, `Scheduler_config`, `Idle_policy`, `Priority`, `current_worker_index`, and the queue/deque/eventcount internals — lives in `ts::`/`ts::detail` like the rest of the library) — priority queue + `std::jthread` worker pool. **Single global instance (2026-07, hardened 2026-08)**: exactly ONE process-wide scheduler, `global_scheduler()` (renamed from `default_scheduler`; reconfigurable holder in `guarded.cpp` — `unique_ptr` in a namespace static + a lock-free `g_fast` read cache, mutex-guarded lazy-init/swap). **At most one worker pool ever runs at a time** — there are no ad-hoc `Scheduler` instances. Reconfigure by teardown+recreate: `configure_scheduler(Scheduler_config)` joins the current workers and builds a new pool; `Scheduler_scope` (RAII, dev-only `tools/scheduler_scope.h` - not public API) reconfigures for a scope and restores on exit — the way to run a block on a specific worker count / idle policy (samples' variant traces use it; tests/benchmarks/tsan that once made ad-hoc instances now reconfigure the global for their scope). NOT thread-safe against concurrent use — a coarse lifecycle op for quiescent points. `graph.execute()` / `ts::launch` / `async` all use the global; `execute()` dropped its `Scheduler&` param. **Construction is factory-gated**: the `Scheduler` ctor is PRIVATE, and `detail::make_scheduler(Scheduler_config)` (a friend, returns `unique_ptr` since `Scheduler` is non-movable) is the only way to build one — used by the global holder (and available to a legitimately-isolated, non-competing object-unit test). Ad-hoc `ts::Scheduler s{cfg}` no longer compiles, enforcing the single-pool invariant at the type level. **Minimal public surface (M8, 2026-08-23)**: `Scheduler`'s user API is `submit` / `worker_count` / `single_threaded` / `quiescent` (plus `Task_func_ptr`, public because `submit` takes it); `worker_idle`/`worker_busy` and the whole `TS_PROFILING` block (accumulators, arm/disarm, `add_*`/`read_*`, `util_bucket_count`, `Busy_slot`/`Bucket_row`) are private, reached by the trace bridges, `tools::Trace_stamps` and the worker-less oracle only through the friend `detail::Scheduler_profiling` (static forwarders, the `Guarded_access` idiom). This implements the old "single-global follow-up." **`current_scheduler` retired (2026-08)**: the `thread_local Scheduler*` "which scheduler" selector is GONE — with one pool there is nothing to select. `current_worker_index >= 0` is now the sole worker-vs-external discriminator (the enqueue fast path, the `parallel_for` fan-out target, the profiling busy-slot selection, and `Parallel_recorder::lane` all key off it); the profiling trace bridges resolve `global_scheduler()` directly (each fires only while a traced run is armed, so the pool exists), routing non-worker callers to the overflow lane consistently — which closed a bug class where a null `current_scheduler` on the frame-loop thread made a metric read 0.0%. `Priority {high, normal, low}` (in `priority.h`, shared with the task core) orders the queue; every queued task route threads a priority to `submit`: `ts::launch(fn, {.priority=p})`, `Guarded::async(fn, {.priority=p})`, `Graph_node::set_priority(p)` — stored on the block, applied at dispatch (incl. pipe-turn-gated). `parallel_for`/`parallel_for_async` helpers inherit the calling task's priority by default (`current_task->flags.priority`, resolved once on the calling thread; `Priority::normal` outside a task) — `Parallel_options{.priority}` overrides; the participating caller runs inline regardless. **One resolution rule for every option struct (S2, 2026-08-23)**: `Dispatch_options::priority`, `Access_options::priority` and `Parallel_options::priority` are all `std::optional<Priority>` resolved through `detail::resolved_priority` (task_block.h — explicit wins, else the calling task's, else `normal`) on the calling thread at the verb — so `obj.async(fn)` from a `high` task runs `high` (the old plain-`Priority` fields silently demoted it to `normal`); `Versioned::publish` resolves at the publish call, not in its later phase-1 continuation. `Parallel_options::max_workers` (S6 — was `concurrency`) is the upper bound on participating executors incl. the caller; `Scheduler_config::num_workers` (was `num_threads`). `parallel_for_async` (S7 — was `async_parallel_for`, the library's only `async_` prefix) honours `Parallel_options::token`: a helper that finds the token requested claims the whole unclaimed tail in one `exchange`, accounts it through `done` unprocessed and raises `skipped`, and the executor whose accounting reaches `n` settles the task CANCELLED (`is_cancelled()`); running chunks finish; one token load per chunk claim. The blocking forms ignore the field (the caller participates and joins). `parallel_for`/`parallel_for_async` fan their helpers out on `global_scheduler()` — with the single pool there is no separate "current" scheduler to route to, so a graph node's slices and an off-worker caller's slices both land on the one running pool (the former `detail::current_or_global_scheduler` selector collapsed to `global_scheduler()`). Per-instance `Idle_policy` via `Scheduler_config` at construction (runtime enum, no measurable hot-path cost), three modes: `spin` = never park, yield-loop (producers never signal); `spin_then_block` (**default**, UE-style) = spin `spin_cycles` scans on the `Event_count` (eventcount, not a semaphore) before parking, producer wakes one per submit (`spin_cycles == 0` degenerates to park-immediately); `handoff` = Go-style spinner handoff (a spinner that finds work promotes a successor before running; producer issues the wake syscall only on the fully-parked 0→1 transition, else a cheap epoch bump — moves wake cost off the producer). Wake latency ~40% lower than a bare park; throughput cost on uncontended streams. See `signal_submit`/`handoff_wait` in `scheduler.cpp`. **Worker-less mode** (`Scheduler_config{.single_threaded = true}`, 2026-07, UE's no-multithreading shape): zero workers; every `submit` executes inline on the submitting thread via a bounded FIFO trampoline (per-thread pending + shared head, reentrant); blocking waits drain pending entries before parking (`detail::drain_serial_pending`, task.h→scheduler.cpp seam); priorities/idle policy inert; deterministic — serves debugging/bisection, deterministic tests, thread-less platforms, low-end fallback. Enabler: pipe turn firing happens AFTER `pipe.mutex` unlock (`collect_admissions` gathers the granted links under the lock, `fire_granted` fires them after) — inline-at-submit would deadlock releasing a pipe under its own held mutex. Worker-less graph runs skip the trace fold. Runtime, not templated — the single reconfigurable global holder + the `thread_local current_worker_index` rule out templating `Scheduler`. **Queues (M2)**: one lock-free MPMC queue per priority (`high`/`low` global-only; the `normal` MPMC doubles as overflow + injector for external submits) plus a per-worker Chase-Lev deque for `normal` (own submits LIFO on the producer fast path, thieves steal FIFO) — replaced the old single mutex-guarded `std::priority_queue` that was the scaling bottleneck. **Busy counters (`TS_PROFILING`)**: per-worker padded `Busy_slot` (completed `ticks` + in-flight `started` — the in-flight part matters: a trace's fold runs INSIDE the settling worker's task, so completed-only counting reads 0 on a 1-worker scheduler); `run_task` times each task ONLY while armed (`arm_busy_tracking` refcount, armed by a traced run's window — disarmed cost is one relaxed load+branch, unmeasurable on the spin throughput series; armed = 2 clock reads/task); `busy_ticks()` = relaxed sum + in-flight elapsed, feeds the trace's core-utilization headline; a per-worker `tasks` counter on the same armed path (`task_count()` = relaxed sum) feeds the trace's task-volume stat (total + mean/run: every task kind, so it far exceeds the node count — game_frame ~135/run baseline, ~153/run optimised). **Time-bucketed utilization**: per-worker `Bucket_row` (padded array of `util_bucket_count`=128 relaxed atomics); `arm_busy_tracking(origin, bucket_width)` sets the window frame + clears rows, `run_task` distributes each armed task's [start,end] busy span across the buckets it spans, `read_bucket_busy` sums per-worker at the fold (published by the run's completion barrier). Bucket width = the trace's prior-makespan estimate / 128 (fixed once; run 1 un-bucketed). Feeds the trace's true per-time utilization background (replaces the old node-concurrency proxy that undercounted `parallel_for`). **Owner attribution (per-node true busy)**: `detail::trace_owner.h` (scheduler-free seam included by `task.h`) — a `current_trace_owner` TLS set by a node body (`Trace_owner_scope` in `run_graph_node`) and inherited by launched sub-work (the `parallel_for` helper's snapshot + a coroutine frame's promise), `Trace_busy_scope` measures each body while armed and routes its span through a bridge (`trace_owner_add`/`trace_owner_armed`, defined+installed in `scheduler.cpp` → `Scheduler::add_owner_busy`) to a per-node `owner_busy_` sink (armed alongside the bucket rows, relaxed, read at fold); so a node's true-busy = body + slices + async fan-out (a `parallel_for` node reads ≫ its wall-time bar). Depends on the `parallel_for` fan-out landing on the one running (traced) pool — which it does now that there is a single global pool. **Task-system cost (body/machinery split, PURE SUBTRACTION, `TS_PROFILING`)**: the overhead metric is now `M = busy − B`, DERIVED — there is NO machinery accumulator (the direct-summed-M apparatus was retired 2026-08, Phase 2 of `docs/profiler-guided-optimization.md`). One per-worker `Busy_slot` accumulator, `body` (B, add-only, single-writer, relaxed), plus `busy` (`ticks`, the run_task-span sum) and a dedicated `orchestration` bucket. In core-time `T = workers × makespan`, every worker-moment is body / machinery / idle: `T = B + M + P`, so **`M = busy − B`** and **`P = T − busy`**, both computed at the fold; the fourth bucket, **orchestration**, is the top-level `execute()` setup that runs OFF any run_task span. Headline **framework overhead = M/(B+M)** (the shipped header labels this "framework overhead", not "machinery"; bands `overhead_ok_share` 0.05 / `overhead_bad_share` 0.15 in `graph_trace.h`) + a `body … µs / framework overhead … µs per run` stats line + the core-time breakdown (body / framework overhead / idle / orchestration as shares of T). Booking: `run_task` books its whole span to `busy` only (no M); the functor's `Trace_busy_scope` credits its own span to B via `trace_body_add`→`add_body_ticks` (add-only, no netting — there is no M to net out of); so machinery `busy − B` per task = setup + completion + successor dispatch. **Option 2 — busy is complete**: a SUCCESSFUL `find_work` scan (`find_work_dispatch`) folds its span into `busy` (not a separate accumulator), so the dispatch cost lands in `M = busy − B` by subtraction; a failed scan is idle, not cost. `Submit_cost_scope` (the fan-out submit B→M reclassification) was DROPPED — an in-functor submit now counts as body; the delta on game_frame was ~0.3 pt on the optimised overhead, below the materiality bar, and the model is simpler. The old load-bearing subtleties are GONE with the netting: no `trace_body_under_run_task` flag (nothing to net an inline body out of — it just credits B), no `machinery_ticks()` in-flight compensation (busy already has it via `busy_ticks()`), no NEGATIVE-M hazard. All gated + armed-only (disarmed = one relaxed load+branch). **The span gate (2026-08-23)**: `Trace_busy_scope` credits B only inside a TIMED `run_task` span (`trace_span_timed` bridge → `Scheduler::in_timed_span`, `started != 0`; a non-worker thread passes, its B lands in the overflow lane) — `run_task` decides "armed" at its start and the scope at its construction, so a task dequeued in the disarmed gap between two traced runs (a leftover `parallel_for` helper) whose functor started after the next arm credited B with no busy behind it; on an oversubscribed CI runner a preemption inside that window was a 10–15 ms B credit and a negative M (the one Debug CI failure, 2026-08-23). Companion test `graph trace body only in timed span`. **Orchestration bucket + worker-less ground truth (2026-08)**: two more pieces close the metric's blind spots. (1) The per-run graph setup (`bind_links_for_run` + node re-arm + indegree init + root dispatch) runs in `execute()` on the calling thread in NO `run_task` span (so absent from `busy`) and scales with node count — a `detail::Trace_setup_scope` (in `trace_owner.h`) → `trace_orchestration_add` bridge → `Scheduler::add_orchestration_ticks` books it to the dedicated **orchestration** bucket (the four-way's fourth term, on top of T). `begin_run` moved ahead of the setup so the snapshot brackets it. **The #3 nesting gap is closed**: the scope books orchestration ONLY when `!current_in_functor`, so a NESTED in-body `execute()` (called from a node body) books nothing — its setup already runs inside the enclosing node's run_task span and is captured by that node's `busy`/`B` accounting; a top-level frame-loop `execute()` (never in-functor) is unaffected. Enabler: an **overflow lane** — `busy_` sized `workers + 1`, a non-worker caller (`current_worker_index < 0`, the frame loop) lands in the trailing slot instead of being dropped (`busy_slot_index`); every trace bridge resolves `global_scheduler()` directly (armed-only so it exists), routing a non-worker caller to that lane. The overflow lane is also what makes B accumulate at all in worker-less mode (no workers). ~11–13 µs/frame on game_frame. (2) A **worker-less ground truth** (the oracle): a `single_threaded` traced run is serial on one thread with no idle, so `overhead_true = (total_wall − B)/total` is the COMPLETE framework cost by pure subtraction (total = the sample's `steady_clock` bracket around the whole `execute().sync()` frame, not the node-span makespan; B read directly off the scheduler's body accumulator, no fold). `--trace` prints the multi-worker `M = busy − B` overhead + the serial floor + their gap (console + SVG headline via `Graph_trace::set_ground_truth_overhead`); the gap (multi-worker ABOVE the floor) is the machinery only workers pay — cross-thread dispatch, pipe hand-off, park/wake — reported as-is, not fudged. game_frame (6-worker trace, 200 frames): baseline overhead 10.2% (B 38.1 ms / M 4.32 ms) vs serial floor 2.2% → gap +8.0 pt, optimised 4.3% (B 38.0 / M 1.71) vs floor 2.2% → gap +2.1 pt; four-way baseline body 80.9 / machinery 9.2 / idle 9.9 / orch 0.0, optimised 92.6 / 4.2 / 3.3 / 0.0 — the metric discriminates coarser batching; upper bound (traced clock brackets + real-node acquire/handoff/dispatch, not comparable to the ~200 ns bare-bench floor). - **`Guarded<T>`** (`guarded.{h,cpp}`) — the access-controlled wrapper; the only sanctioned way to touch a thread-unsafe `T` across threads. Two verbs run `fn(T&)` (write) or `fn(const T&)` (read) on a per-object **reader/writer pipe** (concurrent readers, exclusive writer, FIFO, completion-driven dispatch), mode deduced from the functor's parameter const-ness. Both are EAGER and return a `Task<R>` (awaitable from a coroutine, `sync()`-able only from outside a task); they differ in dispatch, not in color: **`access(fn, opts={})`** is opportunistic — objects the calling task already holds are **lent** (`Access_op::bind_links`, 2026-08: `Access_context::grants(inst, mode)`, the graph's `bind_links_for_run` protocol; no link entered, `num_locks` reduced — all-lent means the body runs inline under the held grants, which SUBSUMES the old `writer_owner == current_task` reentrant arm, now deleted), and the rest are probed **all-or-nothing** by `pipe_try_inline(block)` (every remaining pipe's mutex held at once in canonical order — over no user code — admitting all or none: `queue_head == nullptr && admissible` per pipe, so queued work is never jumped), else the whole set enqueues; **`async(fn, opts={})`** always enqueues (for heavy functors). Options are two aggregates in `task.h`: `Access_options` (`{.token, .priority, .name, .queued}`) on the opportunistic `access` verbs and `Dispatch_options` (the same three minus `queued`) on the always-enqueueing ones; the verb picks inline-vs-enqueued, and `queued` is the single opt-out — read by the `access` verbs at every arity (2026-08; it skips the inline probe, never the lend), and unspellable on `async`/`commit`/`publish`, which take `Dispatch_options` instead (the M2 split, 2026-08-23: no verb takes a field it cannot honour, and `Versioned::publish` stopped dropping `opts.name` on the way). `name` is a `ts::Named` since 2026-08 (M6), not a `const char*`. `Dispatch_options` and `Access_options` are the only two aggregates, and are deliberately NOT related by inheritance - a base subobject cannot be named by a designator, so `{.priority = p}` would stop compiling. Constructs `T` in place; adopting an existing instance is future work. The **awaitable held-grant** form is separate: `auto g = co_await ts::read_write(obj);` / `ts::read_only(obj)` yields a `ts::Access_guard<T, Mode>` (non-copyable AND non-movable — its address is the installed `current_access`) holding the grant for the guard's lifetime; `co_await`ing anything while a guard is live is fatal (`Coroutine_block::guard_depth`). **Multi-object**: the free functions `ts::access(fn, objs...)` / `ts::async(fn, objs...)` (options first: `ts::async({.priority=p}, fn, objs...)`) run `fn(*obj1, *obj2, ...)` over several `Guarded`s at once — per-arg mode from const-ness (`Function_traits`), the block carrying one embedded `Pipe_link` per object and entering them in **canonical (pipe-address) order** through the sequential cascade (`async_build_modes` sorts by pipe address, seeds `num_locks`, then `pipe_enter_first`; a repeated object is fatal - declare each object once; strictness applies uniformly to `add_node` and the multi-object guards, and can be relaxed back to write-wins dedup on demand, 2026-08-18); each admitted turn releases one lock and enters the next link, and the last dispatches the body under an `Access_context` declaring all. Deadlock-free by the globally canonical order — the SAME cascade graph nodes use, so nodes and multi-object accesses cannot deadlock against each other. **Multi-object `access` returns the op too (2026-08, `docs/multi-access-op-design.md`)**: `Access_op` is now variadic (`template<typename... Args>`, objects first / body last, split by `detail::Op_traits`; `Access_op<T, Body>` keeps its exact prior meaning, enforced by `detail::op_matches_single_object_deduction` static_asserts, and a tagged position spells `Access_arg<T, M>` in the type), carries N links/pipes/modes in CANONICAL order plus instances/epochs/ranks in DECLARATION order (`decl_index` maps between them), and `ts::access(fn, objs...)` builds it in caller storage via `detail::Access_op_maker` (zero-alloc at every arity; `ts::async` unchanged). Arity is `static_assert`ed against `Access_context::max_entries`. A caller holding only READ where the body writes is fatal (the graph's nested-run rule, inherited). **Access-mode deduction, one spelling rule everywhere (A3+A4, 2026-07)**: non-generic functors are introspected (`Function_traits`; by-value / `T&&` resource params are `static_assert`-rejected — a copy silently discards writes); **generic lambdas deduce too**, via the rvalue-bindability probe (`detail::probed_mode` — `const auto&`/`auto&&` binds an rvalue → read, `auto&` cannot → write), so `[](const auto& p, auto& a)` works bare, no tags. Every READ position (deduced/probed/tagged) invokes the body with `const T&` (`detail::mode_ref`), so mutating under a read classification is a compile error. Constraint/return-type ORDER is load-bearing: the mode gate (`accessor_mode`, `Accessor_result`) is evaluated before any invocability probe against `const T&`, because probing a generic lambda deduces its return type → instantiates the body → hard error for a mutating body (not SFINAE); the mode-first pair is factored as `detail::Read_only_accessor`/`Read_write_accessor` (one spelling — `Guarded`'s four verbs and `Versioned::read`, which previously carried a bare pre-hardening `Async_accessor` tier that re-opened the trap), so misuse rejects as constraints-not-satisfied at the user's call site. Residual closed (2026-08-25): a second probe invokes the read-classified position with a `detail::Non_copyable<T>` lvalue (non-copyable, derived from `T`) - an `auto` by-value parameter cannot copy-initialize from it, so the misuse is a `static_assert` (message points at the `as_read_only` tag for bodies that copy deliberately); skipped for final/non-class `T`, where the silent copy remains documented. `ts::as_read_only(g)`/`as_read_write(g)` tags (`detail::Access_arg<T, M>`) remain as explicit style, the `auto&&`-that-writes escape, and legal write-over-declaration; all args tagged or none (mixing is a `static_assert`); applies to `ts::access`/`ts::async` and graph `add_node`. One unified builder per surface: `async_build_modes` / `fill_node_modes` (deduced/probed/tagged tiers).
- **The pipe** (`detail::Pipe` in `guarded.h`, `detail::Pipe_link` in `detail/pipe_link.h`, implementation in `guarded.cpp`) — the per-object reader/writer serializer, rebuilt 2026-08 (`docs/pipe-rebase.md` §0; the lock-free tail chain was implemented, stress-tested and RETIRED on its own perf gate — 22 producers on one pipe measured 798 ns/op vs ~1050 uncontended, so the mutex was never the bottleneck, while every reader-group protocol piece burned). Shape: one `std::mutex`, an intrusive FIFO of **embedded** `Pipe_link`s (`queue_head`/`queue_tail`; no `Job`, no `std::deque`, no per-entry closures), `active_readers`/`writer_active`, a `condition_variable idle` for the teardown drain, and an always-on `std::atomic<Task_control_block*> writer_owner` (identity only, never dereferenced — it is what `Deferred::commit` and `Guarded::access`'s reentrant arm key off, so it cannot live behind `TS_SAFETY_CHECKS`). A `Pipe_link` is `{next, owner, pipe, index, mode}`; a null `owner` marks a HOLD entry (`pipe_acquire`'s node — the one allocating pipe path). **Pipe turns are `num_locks` prerequisites**: a task seeds `num_locks` with its `pipe_count`, `pipe_enter_first` enters link 0, and each admitted turn fires `release(owner)` which enters the NEXT link — the sequential canonical (pipe-address-ordered) cascade — with the last release dispatching through `dispatch_ready` (priority, inline, cancellation, worker-less all uniform). ONE cascade serves dynamic multi-object `async` AND graph nodes, which deleted `Multi_async_state`, its `std::map`, the `on_acquired` closures, the graph's `acquire_next` pipe walk, `preheld`/`handoff_target`, and the explicit graph write handoff. Admission collects granted links under the mutex (`collect_admissions`) and fires them after unlock (`fire_granted`) — firing under the lock would self-deadlock in worker-less mode. The drain notify is done UNDER the mutex, which makes it structurally immune to the UE `FPipe` teardown UAF (that race is a lock-free-notify artifact; `fire_granted` also never binds `Pipe&`, so nothing touches a pipe a waiter may have freed).
- **`Task<R>`** (`task.h`) — the ONE completion primitive, for every result-bearing producer (`access`/`async`/`launch`/`execute`/a coroutine): `is_done()`, `is_cancelled()`, `sync()` (blocking, returns `const R&`, non-consuming, any number of readers), `take()` (blocking, moves the result out — the single destructive consume). **The blue boundary**: `sync()`/`take()` are legal ONLY outside a task; inside one (`current_task != nullptr`) they are **fatal** under `TS_SAFETY_CHECKS`, settled target or not - the check fires on the call, not on whether this run would park (TODO 6.10) (`blocking_sync_diagnose`, seam task.h→guarded.cpp — a sharp same-object message when the target is an access on an object the current context holds, a general never-park message otherwise). Inside a task the verb is `co_await`. The one exemption is `parallel_for`'s internal join, which waits on group state directly and never enters `sync_wait`. `Task` is a completion handle only — it does not carry graph identity (see `Graph_node`). The shared state is a **fully monomorphic** `detail::Task_control_block` (**248 B** shipping / 280 B checked — the harness adds the grant bookkeeping; not templated at all — the result is erased behind `void* result_ptr` and composed via a `Result_block<R>` wrapper the handle aliases; no `<void>` specialization; no virtual dispatch). The size fell 320→280 as retraction deletions dropped the `prerequisites` vector, 280→264 when `successors` collapsed to the single `nested_parent` slot, and 264→248 when the generation/reuse substrate was retired (`dispatch_arg` deleted, `run_state` reduced to the one-byte `body_claimed`). The **body** lives in the block too: `async`/`ts::launch(fn)` store it in an `Executable<Body,R>` wrapper reached via the block's `execute` fn-ptr; a coroutine's promise derives from the block (frame/block fusion, one allocation). **Wrappers derive from the block (2026-08, G2)**: every storage wrapper (`Executable`, `Piped_executable`, `Parallel_base`, `Graph_node_block`, `Promise_base`) inherits `Task_control_block` — recovery is a standard-defined `static_cast` to the derived type (the `detail::Block_backed<Derived>` CRTP helper supplies `from()` + a plain-`delete` `install_destroy()`), replacing the first-member `reinterpret_cast` idiom that was only conditionally supported. **The lock-counter** (`num_locks` + the single `nested_parent` slot) is what everything gates on: below `execution_flag` it counts unmet obligations (pipe turns), above it counts a pending `add_nested` completion (a coroutine node's frame / a nested graph run); `release()` has three thresholds — `0` → `dispatch_ready`, `execution_flag` → complete, `== pipe_count` → `pipe_enter_first` (the pipe cascade trigger). `detail::submit_ready` bridges the counter to the scheduler. **Launch verb**: `ts::launch(fn, Dispatch_options{.token, .priority})` is the one bare-task verb — free-running (nothing joins it — the cross-frame form), inherits no grant (a detached child's window can close while it runs). Fan out over a holder's data with `ts::parallel_for` (grant-inheriting helpers, synchronous join). The `ts::nested`/`ts::Task_scope`/`ts::join_nested` scoped-launch verbs were **removed (2026-08)** as an unsafe concurrent grant-inheriting child (rationale in `docs/coroutine-first.md` §4.3); only `detail::add_nested` survives as graph-internal completion-gating. **`Signal`** is a bodyless `Task<void>` completed by hand via `trigger()` (idempotent) with `reset()` for re-arming — the done-signal / barrier / phase gate (UE's `FTaskEvent`), and the sanctioned bridge for OS/GPU completions into `co_await`. **Cancellation**: `Cancellation_source`/`token` (cooperative); every verb takes an optional token; not-yet-started work is skipped and cancellation propagates as a completion state (`Task::is_cancelled()`); awaiting or `sync()`ing a cancelled VALUE task is fatal (check first), a cancelled `void` one resumes/unblocks normally. The two cancellation-tolerant consumes branch instead of fatalling: `try_take()` (never blocks — empty when unsettled OR cancelled, so it is also legal inside a task) and `as_optional()` (`co_await t.as_optional()` waits, then yields empty on cancellation); both move the result out, like `take()`, and neither exists for `void`. **Body-level early-out (opt-in)**: any body declaring a trailing `Cancellation_token` parameter receives the block's token (forwarded by `Executable::run`) so it can poll `is_cancel_requested()` and early-out for cancellation arriving *mid-run* — a cooperative return settles the task **completed**, not cancelled. **Push notification**: `Cancel_callback(token, fn)` (RAII, `std::stop_callback`-style) — `request_cancel()` fires registered callbacks synchronously, for work that blocks rather than polls; source/token/callback share a `detail::Cancel_state`. **Deleted by the coroutine-first transformation (2026-08)**: `then`, `when_all`, the `ts::task` builder and `after`/`add_prerequisite`, retraction (deep and shallow) with its claim/generation machinery, executable-task reuse, and the dynamic `run_inline` surface — every one is now a compile error, with `co_await` as the replacement. `dispatch_ready`/`inline_pending` survive but are graph-internal (`Graph_node::set_inline`). See `docs/coroutine-first.md` and `docs/task-internals.md`.

Node blocks + the `Run_state` are built at `compile()` and re-armed per run (nodes dispatch via the raw scheduler API; completion via the block's persistent `on_complete` fn-ptr, not a per-run continuation), so a run allocates only its `done` handle — re-runs are essentially allocation-free (~19% faster than per-run blocks). The graph is movable (`execute()` refreshes the blocks' back-pointers); runs are sequential (one at a time). Nodes access their objects **directly** (bypassing per-call dispatch), so each node takes a pipe turn on every object it touches before running and releases at completion — a concurrent `Guarded::async` on the same object queues behind the node that holds it instead of racing it (the harness does *not* catch that race — both sides declare access). Since the pipe rebase this is the SAME cascade as multi-object `async`: each node's `Pipe_link`s live in a contiguous `compile()`-time slab (`node_links_`), bound in ascending pipe-address order and re-armed per run, and the node's cascade starts at data-ready. An object is held only over each accessor's `[first turn, completion]` window — free in the gaps for async, and a **reader** node holds it as a reader so a concurrent async read (or another reader node) overlaps; a **writer** node is exclusive. The explicit object handoff (`preheld`/`handoff_target`) is GONE with the rebase — its optimization survives only opportunistically, when a successor's link is already queued at the predecessor's release, so release + next admission happen in one mutex pass. **Inline dispatch** (`Graph_node::set_inline()`) survives: a ready node runs on the thread that settled its last prerequisite via the shared `dispatch_ready` trampoline. **Nested graph runs (2026-08, `docs/coroutine-first.md` §4.8)**: `co_await inner.execute()` from a node works via the LEND protocol — `bind_links_for_run` intersects the inner graph's compiled access set with the caller's `Access_context` at every `execute()` and re-binds the `compile()`-time link slab to only the objects the run must take turns on, so a lent object's turn is simply never taken (an awaited inner run is contained in the caller's grant window, which is already the exclusion it needs; without this the inner node queues behind the grant its suspended caller holds — deadlock). Inner conflict edges still order inner nodes among themselves on a lent object, and the pipe never sees the lend (external `async`s queue behind the caller's hold as before). Recursion composes by construction. A nested run also JOINS the caller's implicit scope by default, so an un-awaited inner run cannot float; `execute({.detach = true})` opts out of both (a detached run is not contained, so it gets no lend and queues like external work). Three fatals (`TS_SAFETY_CHECKS`), each with a companion test: a caller holding READ where the inner graph writes; lending while an earlier un-awaited nested run of the caller is still in flight; and `execute()` while a run of that graph is in flight — the last closing a previously unguarded `Run_state` corruption. One run per graph instance remains the rule (TODO 2.3 is the relaxation). **Concurrent runs of DIFFERENT graphs over shared objects are supported** (validated 2026-08): canonical pipe-address ordering makes a cross-graph wait cycle impossible and the pipe serializes their conflicting nodes as it would a node against an async — safe, but cross-graph ORDERING is nondeterministic, so don't build semantics on it. Gated by `TS_SAFETY_CHECKS`.
- **Waiting-rule policy** (`rules.h`, design of record `docs/waiting-rule-policy.md`) — the coroutine-first waiting rules (`docs/coroutine-first.md` §2) are enforced by runtime checks that fatal, and each is separately (1) compiled in via `TS_ENABLED_RULES` (a bitmask of `TS_RULE_*`) and (2) opted out of per scope via `ts::Relaxed_scope` for the rules that permit it. `ts::Rule` mirrors the bits: **`in_task_sync`** (`sync()`/`take()` inside a task), **`await_under_guard`** (`co_await` while a `Access_guard` is live), **`access_rank`** (awaiting an object out of declared rank order), **`circular_wait`** (a held-grant → awaited-pipe wait cycle), **`deadlock_net`** (quiescence with no possible external wakeup). Rule classes: `advisory` (`in_task_sync|access_rank|circular_wait` — a scoped `Relaxed_scope` opt-out, "I uphold this by means the library can't see"), `structural` (`await_under_guard` — compile-out-only, its absence corrupts rather than merely permits, so it is the ONE rule shipping keeps), `net` (`deadlock_net` — global, unscopable). `set_default_relaxed_rules(Rule)` is a process-wide advisory-relaxation baseline. `circular_wait`/`access_rank` read grant bookkeeping that exists only under `TS_SAFETY_CHECKS`, so they can't outlive it whatever the policy asks (the EFFECTIVE mask = policy ∩ build support). `rule_enforced(rule)` is the one predicate a check calls, only AFTER the cheap hazard condition is already true (the relaxation lookup stays off the common path). **`detail::relaxed_rules` is reached ONLY through `detail::relaxed_load()`/`relaxed_store(unsigned)`, both `TS_DETAIL_NO_INLINE` (2026-08-22)** - a compiler may resolve a thread-local's block address once and keep it in a coroutine frame across a suspension, so an INLINED read after a cross-thread resume answers for the SUSPENDING thread (MSVC 19.51 does; the class is cross-compiler with an incomplete upstream fix - LLVM #47179 / #63022 / D92661, and it extends to anything thread-identifying, e.g. clang's `pthread_self()` case and LLVM #72006). The barrier lives in the accessors, so every toucher (`relaxed_bits`, `Relaxed_scope` ctor/dtor, `Relaxed_carrier`, `snapshot_relaxed`, `Inherited_relaxed_scope`) inherits it and none carries its own `TS_DETAIL_NO_INLINE`; load/store BY VALUE (an `unsigned&` accessor re-opens the hazard one level up - the Rust `thread_local!`+`.with()` shape). Regression test "rules relaxed scope reads the resuming thread" (it fails again if the accessors are made inlinable - verified both directions); rationale in `docs/waiting-rule-policy.md` §4.1. A `Relaxed_scope` entered in a coroutine body follows the ambient task state, not the thread (`Relaxed_carrier` on the promise re-installs it around every segment). **`ts::Rank`** (`access.h`) — a declared lock order (`Guarded(Named, Rank, args...)`), NOT defaulted, required only for objects dynamically awaited while another grant is held; the `access_rank` rule fatals on an out-of-order await. **Deadlock report, three tiers** (`docs/waiting-rule-policy.md` §7): tiers 1 (the `circular_wait` cycle) and 2 (the `deadlock_net` quiescence net — the scheduler idle with nothing externally outstanding for `set_deadlock_net_window`, default 2 s) are free and always present; tier 3 is `TS_SUSPENSION_REGISTRY` — an opt-in per-suspension registry (who is suspended, what they await, what they hold), default ON in DEBUG only (a linked-list insert/remove per suspension, ~30 ns, ~8% on the suspend/resume microbench), which forces `TS_DEBUG_NAMES` on (a registry of block pointers is not a diagnostic). **`ts::External_wait`** (`task.h`) — the `deadlock_net` escape: hold one while a wakeup owned by a thread the scheduler doesn't run (OS I/O, GPU fence, a `Signal` from a dedicated thread, a `Frame_gate` `open()`) is outstanding, so the net doesn't false-positive; a FORGOTTEN registration produces a false deadlock report, which is why the report names the type. **`ts::Named`** (`named.h`) — the one unified debug-identity type for graph nodes (required), guarded objects (required), and tasks (optional, `Dispatch_options::name`/`Access_options::name` — both are a `ts::Named` since 2026-08 (M6), not a `const char*`: the call SITE is captured by the verb's own defaulted `source_location`, so an unnamed task is still identified, EXCEPT on the multi-object verbs, which end in an object pack and can carry no defaulted `source_location` — there `{.name = ts::Named{}}` is the only way to capture the site, and `detail::named_from` prefers the option's `Named` when non-empty). A `Named` is a literal OR a `{}` call-site capture (`file`+`line` only, three words); `named_display` renders it. The load-bearing library rule: a defaulted `source_location` captures the CALLER, so it must sit on the OUTERMOST function the user calls and be passed down explicitly — an inner helper re-defaulting it captures the library header (`tests/named_tests.cpp` asserts captured names point into the test file). ## Terminology

Use these terms precisely, in code and discussion:

- **spin waiting** — yielding in a loop until a condition holds (e.g. the worker idling on an empty queue, or a fixed-duration `spin()`). Does no other work.
- **busy waiting** — doing *unrelated* work while waiting, e.g. a thread that pops and executes other queued tasks while waiting for a specific task to complete. Usually a bad idea (stack growth, latency, priority inversion). Not the same as spin waiting.

## Design Principles & Lessons

- **Granularity decides parallelism.** Whole-object (system-level) access serializes every reader against any writer, collapsing the DAG toward sequential. Shard mutable state — the sample double-buffers transforms (`world_xf_prev` read by early systems, `world_xf` written by propagation and read by late systems, swapped per frame) so many readers don't contend with the writer. The central tension: static safety wants coarse access sets, performance wants fine ones.
- **Completeness hazard.** The graph's safety holds only if its access declarations are *complete*. A manual task or an escaped reference touching a system the graph believes it owns races — and the graph can *promote* a latent bug to a live one by manufacturing parallelism around it. The harness is the runtime oracle for undeclared access.
- **Never block inside a graph node / task — suspend instead.** An in-task `sync()`/`take()` on unsettled work is FATAL (checked builds), not merely discouraged: blocking ties up a worker and risks deadlock under worker exhaustion, and there is no retraction left to rescue it. Consuming a result inside a task means `co_await` (the frame suspends, the worker is freed, grants are held across the suspension); outside a task — the main loop, an external thread, a test — `sync()` is the sanctioned boundary verb. `parallel_for`'s join is the one structural exemption (it waits only on work that provably occupies a worker).
- **Suspension under a grant, in preference order** (`docs/coroutine-first.md` §2). Under a held grant a task may safely suspend on (a) its own spawned children (they inherit the grant, no cycle can pass through the holder's objects) and (b) the same object (reentrancy — `writer_owner == current task` runs inline under the grant). Suspending on a FOREIGN object is safe only if no waits-for cycle forms, which is a global property the caller cannot see locally — the failure mode is a suspended ABBA deadlock where no thread parks and the run silently never completes. Prefer, highest first: declare the object on the node and let `compile()` order it; a `Versioned` snapshot when last-frame data suffices; `Deferred` staging for outward writes; awaited dynamic access as the residual (short bodies, read mode). The waits-for cycle detector catches the residual case in checked builds.
- **Sync state shared across threads must outlive every participant** — heap it (`shared_ptr`), never leave it on a stack frame the initiator may unwind first. (This cost a real use-after-free in `parallel_for`: the caller returned on `completed == chunks` and unwound while a helper still touched the stack counters.)
- Prefer per-instance runtime config over templating when a `thread_local` singleton would fracture across instantiations. Prefer a counting semaphore over a condition variable for worker wake (decouples from the queue mutex; survives a future lock-free queue). Prefer intrusive / zero-alloc on hot paths; avoid virtual dispatch.
- **Prefer intrusive ref-counting over `std::shared_ptr` for types we control.** Use the generic `detail::Ref_counted<T>` (CRTP base) + `detail::Ref_ptr<T>` handle + `detail::make_ref<T>()` in `ref_count.h`: one allocation (not two), a one-pointer handle (not two words), fewer atomics. Reserve `std::shared_ptr` for interop with external types. `Task_control_block`/`Task_ptr` keep their own hand-rolled variant (the block is a base of the `Executable`/promise wrappers, so it needs a `destroy` thunk rather than `delete T*`). Converted so far: `Cancel_state` (`Multi_async_state` and `when_all`'s `Join_state` were converted and then deleted outright by the pipe rebase and the coroutine-first transformation).
- **Allocation discipline (hot paths).** Never spray separate heap allocations for individual small fields — the deleted `when_all` was the cautionary case (four `make_shared` for a slots tuple, an `atomic<int>`, an `atomic<bool>`, and a `std::function`, plus two blocks = ~6 allocs/join, the worst per-op offender the library ever had). **One state struct, one allocation** (ideally the intrusive block itself); fold counters/flags/continuations in as members. The pattern is now standard here: `Piped_executable<Body,R,N>` puts block + result + body + N pipe links in one allocation, and `Task_promise<R>` puts block + result inside the coroutine frame. A per-type recycling free-list is trivial because each `Exec<Body,R>`/`Result_block<R>` instantiation is a *constant* size (variable across types, const per type). Reserve bump/linear (arena) allocation for provably scope-bounded lifetimes (a `parallel_for`, a graph run, a frame with no escaping tasks). Prefer a tunable-SBO callable over `std::move_only_function`/`std::function` (size the inline buffer to the common task-functor size so the closure never heaps), and intrusive, dependent-side links for the block's last edge vector, `continuations` (`prerequisites` is gone with retraction, and `successors` collapsed to a single `nested_parent` pointer once the audit showed its fan-out was structurally 0-or-1 — 24 B and an allocation for one pointer). See `docs/TODO.md` §4 (4.1/4.2/4.7) for the ranked plan.
- **Debugging flaky crashes**: localize with `main`'s `--tests` / `--bench` / `--stress`, categorize exit codes (1 = a `TS_CHECK` failure via `summary()`; `0xC0000005` = an access violation), and build `/p:EnableASAN=true` to get the faulting stack. Get the stack before theorizing — inspection alone misled twice.

## VS Project

The build is split across two hand-maintained VS projects (VS does not auto-discover files), mirroring the CMake targets: **`macrame.vcxproj`** — the static LIBRARY (`macrame.lib`): the 6 core `src/*.cpp` + all headers (`include/ts/**`, `tools/**`); and **`macrame_playground.vcxproj`** — the driver EXE (`macrame_playground.exe`; a `ProjectReference` links the library): `main.cpp`, `mem_profile.cpp`, the samples, the benchmarks, the tests, and `tsan_main.cpp` (compiled with `TS_TSAN_NO_MAIN` - VS-project-only, for Windows compile-coverage of the TSan stress code; it is NOT in the CMake driver, whose TSan build is the separate Linux `ts_tsan` target). Whenever you create a new `.cpp` or `.h`, add it to the RIGHT project's `<ItemGroup>` (path-including-subfolder): a **core** `src/*.cpp` or any header (`include/ts/**`, `tools/**`) → `macrame.vcxproj` (`<ClCompile>`/`<ClInclude>`); a **test/sample/benchmark** `.cpp` → `macrame_playground.vcxproj` (`<ClCompile>`). **AND add the same entry to that project's `.filters`** with a `<Filter>` matching its directory (`src`, `include\ts`, `include\ts\detail`, `tests`, `sample`, `benchmarks`, `tools`, …; the `.vcxproj` controls what *builds*, the `.filters` the Solution Explorer tree — a file added only to the `.vcxproj` builds but lands ungrouped at the project root). **AND add it to the matching `CMakeLists.txt` list** — `TS_CORE_SOURCES` for a core `.cpp`, `TS_SAMPLE_SOURCES`/`TS_DRIVER_SOURCES` for a driver `.cpp`. CI builds via CMake, not the `.vcxproj`, so a source in a `.vcxproj` but missing from `CMakeLists.txt` links fine locally yet fails CI at link with unresolved externals (this broke every Windows CI job once — fixed in `7f065c9`/`32bc9e3`). The lists to keep consistent: the two `.vcxproj` `<ClCompile>` sets (partitioned — core in the library, driver in the playground), their two `.filters`, and `CMakeLists.txt`'s three source variables. Include dirs: the library's `AdditionalIncludeDirectories` is `include;tools`; the playground's is `include;tests;benchmarks;sample;tools`.

Layout: public headers in `include/ts/`, internal (reachable-but-undocumented) headers in `include/ts/detail/`, all implementation `.cpp` (plus the `main.cpp` driver and the dev-only `mem_profile.cpp`) in `src/`; tests in `tests/`, benchmarks in `benchmarks/`, sample in `sample/`, profiling/visualization/dev tooling headers in `tools/` (header-only: `dot_writer.h`, `graph_trace.h`, `graph_introspect.h`, `trace_stamps.h`, `mem_profile.h`; `static_task_graph.cpp` consumes them via ONE unconditional include of `graph_introspect.h` — all `TS_PROFILING` gating and null checks live inside the tools headers, which stub to no-ops when it is 0). The x64 configs set `AdditionalIncludeDirectories` per project (see the VS Project section above): the library gets `include;tools`, the playground `include;tests;benchmarks;sample;tools`. Includes of library headers are always **`ts/`-prefixed** — `#include "ts/guarded.h"`, `#include "ts/detail/journal.h"` — even from inside `include/ts/` headers themselves (the bare form would resolve via the compiler's current-directory rule and reintroduce path ambiguity). Local headers within `tests/`/`sample/`/`benchmarks/`/`src/` stay relative (`#include "harness.h"`, `#include "mem_profile.h"`).

Tests use the harness in `tests/harness.h`: `TS_CHECK(cond)` (non-fatal, prints a stacktrace on failure), `run(name, fn)`, `summary()`. **Config-conditional tests use `run_if(predicate, reason, name, fn)`, never `#if` around the registration** — a test wrapped in `#if` vanishes silently, which is how the Shipping configuration accumulated six failures and a crash unnoticed; `run_if` prints `[skip] name (reason)` and `summary()` reports `N skipped (not applicable in this configuration)`. The predicates are named constants in `harness.h` (`with_harness`, `with_profiling`, `with_rule_*`). A **death** test must name the switch that compiles in the fatal it expects, not merely `with_harness`: with the fatal absent the child does not abort and usually does the thing the fatal prevented — generally a deadlock, so the parent hangs in `_spawnl(_P_WAIT)` rather than failing. Each group lives in its own `tests/<group>_tests.{h,cpp}` with a `run_<group>_tests()` entry, wired into `run_all_tests()` in `tests/tests.cpp` (currently scheduler, access, guarded, pipe, task, graph, parallel, coroutine, integration, deferred, versioned, event_bus, named, rules; shared fixtures — `Rw_probe` and friends — in `tests/test_util.h`). Fatal paths are exercised via subprocess death tests (`ts::test::expect_death("<scenario>")` + a case in `run_death_scenario`).

`main` takes isolation/stress args (no arg = run everything): `--tests` (suite only, returns the failure count as exit code), `--bench` (benchmarks only), `--stress` (sample only, many frames at a fast scale — dense workload for sanitizers), `--death <scenario>` (internal, the death-test child). These exist to localize flaky failures: run one component in a loop, categorizing exit codes (1 = a `TS_CHECK` failure via `summary()`; `0xC0000005` = an actual access violation), and build with `/p:EnableASAN=true` to get the faulting stack rather than guessing.

## Session Guidance

- **Integration and publication require the author's explicit, standalone approval — never bundle them into a larger task.** These actions each need their own yes, asked as its own question at the moment of the action, not inferred from approval of a worklist or plan that happens to contain them: (1) merging or fast-forwarding a feature branch into `master`, or otherwise promoting branch work to `master`; (2) `git push` to any remote; (3) deleting or force-moving a branch, tag, or worktree; (4) history rewrites (rebase-onto-master, force-push, filter). Committing work-in-progress to a feature branch, or to `master` when the author has directed the current work there, does not need a fresh yes — the gate is on *integration and outward publication*, not on saving progress. When a plan reaches one of these steps, STOP and ask explicitly ("ready to merge X into master?" / "push to origin?") even if the plan was approved as a whole. Rationale: the pipe/coroutine-first branch was once promoted to `master` inside an approved worklist and the author missed it; integration points must be visible decisions.
- Multiple sessions will work on different aspects — read this file for context each time
- **Public docs contract**: `docs/guide.md` (user guide — mid-level devs, MT-literate, not gamedev) and `docs/design.md` (design rationale — expert engine devs) are the two public-facing documents; **update them with every push** that changes public API, behavior, or design decisions. `README.md` is the pitch + teaser only (don't duplicate the guide). This file (CLAUDE.md) stays internal, LLM-oriented.
- **Docs prose style (author-calibrated 2026-08-21)**: markdown docs and the README are plain, technical, and unsold. Cut, don't just flag: (1) selling/poetic adjectives and intensifiers — "enormous", "vast", "sheer", "blazing", "powerful", "daunting", "dramatic", "marquee", "brutal", "the bet", praise-word "elegant"/"beautiful"; (2) pretentious vocabulary — "forensic(s)", "crucible", rhetorically-used "thesis" (say "argument"/"idea"/"position"); (3) editorializing asides that add no content ("— just as valuable —", "no less important", self-congratulatory parentheticals); (4) rhetorical-contrast flourishes for cadence ("measurable rather than rhetorical" → "the answer can be measured"; dramatic "X, not Y" pairs); (5) slogan/imperative section headings → plain descriptive noun phrases that name the thing ("lend, don't re-acquire" → "the lend protocol"); (6) marketing verbs ("unleash", "supercharge", "crush", "shine"); (7) **volatile counts** - do not state numbers that drift with the code (node/edge counts, test/check counts, system counts, file counts, line counts). Describe the shape instead ("the frame's ~30 systems", "the suite", "the library sources under `src/`") or point at the artifact that regenerates it. An approximate figure with a `~` is fine where the magnitude is the point; an exact count is a maintenance trap that silently goes stale, and docs are not the place to assert it. Dated measurements tied to a stated config (benchmark timings, utilization percentages, allocation counts) are NOT volatile counts - keep those, with their date/config. PRESERVE all technical content, mechanism names, cross-references, code identifiers, and the density appropriate to the audience — plainer ≠ dumbed down; only DELETE a sentence when it is purely rhetoric, otherwise state its content plainly. Em-dashes are fine in markdown (the single-hyphen rule governs only code comments and emitted strings). This is separate from the code-comment tone rules above (which forbid all-caps emphasis, exclamation marks, and em-dashes in comments/messages).

Same for documents: number the headings/items of reports, surveys, and design docs whenever referencing them in discussion makes sense (idea lists, option menus, findings). Numbers are stable IDs — mark items done/rejected, don't renumber (the TODO.md convention).

Launch a `fork` (inherits context) or a fresh agent, keep chatting, and fold in its findings when it reports. Reserve the main session for design discussion and the actual edits.
- **Stream failures from long verification loops — don't wait for a final total.** A repeat loop should surface a hang/failure the instant it happens so investigation can start while the rest of the loop runs. Use the streaming pattern (emit one line per hang/failure; a final "done" line) rather than one summary at the end — e.g. a loop that runs each config under a per-run timeout and echoes only on `timeout`/non-zero-exit/`ASan`/`N failures`. Note: `Start-Process`'s `$p.ExitCode` reads `$null` on success in this setup (a known quirk) — check the real exit via direct invocation + the `"N failures"` line, not `Start-Process`'s exit code, or the loop will report false failures.
- **Testing is proportional to the magnitude of the change** (author, 2026-08-23) — to what it can actually break. A type/signature/rename change is verified by building and running the suite once; docs need nothing; a change to a concurrent path (scheduler, the pipe, guard, awaiters, `parallel_for`) gets a short `--tests --repeat N --workers 2` plus a **negative check** (revert the fix, watch the test fail — cheap, and the only proof a test can fail); only a hunt for a known intermittent gets the full apparatus (long repeats, several configs, load). Do not run by hand what a hook or CI already runs: the pre-push hook runs the suite under TSan (`tsan/run.sh`, WSL) on every push touching C++, and CI's `linux-tsan` job does the same. Rationale and the tools: `tmp/docs/intermittent-failures.md` (internal, not in the repo) §4.
- After any change to concurrent code, the pre-push TSan gate is the sanitizer pass; run `bash tsan/run.sh` by hand only when hunting (Linux or WSL — TSan has no Windows runtime, see `tsan/README.md`). On Windows, ASan (`/p:EnableASAN=true`) + stress loops are the fallback (they catch memory bugs/UAF, not pure data races).
- Code style:
  - Type names are `Snake_case`: capitalized first letter, underscores between words — `Static_task_graph`, `Access_context`, `Guarded`, `Task`. This applies to all types including class templates (`Task<R>`, not `task<R>`).
  - `snake_case` for members/locals/functions; trailing `_` for private members.
  - Avoid single-character names except in very short scopes (a loop index, a one-line lambda parameter). A variable that lives across a whole function gets a real name (`graph`, not `g`; `world`, not `w`).
  - Lines up to 120 characters (`.clang-format` `ColumnLimit: 120`). Prefer one line where it fits — don't wrap at the old 100.
  - Braces on control statements (`if`/`else`, `for`, `while`): a branch or loop body whose statement spans multiple lines is always braced — including a nested loop and a call carrying a multi-line lambda (a nested-`for` stack is braced at every level whose body is multi-line). When one branch of an `if`/`else` is braced, brace both. Only a single-line body (with a single-line counterpart, for `if`/`else`) may omit braces.
  - **Acronyms/initialisms stay ALL-CAPS inside any identifier**: `write_DOT_dump`, `write_SVG`, `dur_P50`, `DOT_path`; a type starting with one is all-caps too (`DOT_writer`). Ordinary contractions are not acronyms and stay lowercase (`nav`, `xf`, `dur`, `min`), as do unit suffixes (`_us`, `_ms`). File names remain lower snake_case regardless (`dot_writer.h`).
  - Allman braces (opening `{` always on its own line, including namespaces, class/struct declarations, and lambdas):
    ```
    auto lambda = []()
    {
    };
    ```
    Short lambdas may stay one-liners (`[](int x){ return x + 1; }`); use Allman only when the body spans multiple lines.
  - Never align code or comments with padding spaces (no aligning `=`, parameters, trailing args/comments, or braces across lines). Single space only.
  - Safety-only state is FULLY gated by `TS_SAFETY_CHECKS` — fields included, not just behavior (`Pipe::write_epoch`, `Pipe::graph_refs`, `Access_context::Entry`'s epoch pair): shipping carries no dead bytes for the harness. The only unconditional exceptions are state that BEHAVIOR keys off, not just diagnostics — `Pipe::writer_owner` (`Deferred::commit`'s auto-dispatch and `access`'s reentrant arm read it in every build) — and genuinely free storage such as a spare bit in an existing packed byte. Mixed-config TUs are an ODR violation regardless of layout; the link-time tripwire in `access.h` (`detect_mismatch` on MSVC, a config-named anchor symbol elsewhere) turns that mistake into a link error.
  - In comments, wrap references to code identifiers (type, function, variable, member names) in backticks: `Guarded`, `pipe_enter_first`, `current_access`.
  - Comments explain contracts and behavior, never C++ mechanics: no narrating why a forward declaration exists, why a type sits at namespace scope rather than nested, or that something "is an aggregate" - the reader is an expert and the code shows it. No house-style meta either ("house style alongside `X`"). A forward declaration gets at most a terse trailing note naming what the entity is; its real doc lives at the definition. Each fact lives in exactly one comment, at the entity it describes - no free-floating orientation paragraphs that restate a nearby entity's doc (author 2026-08-17, derived from the static_task_graph.h comment trims).
  - Public API headers read as interfaces: a public class declaration contains declarations only - method bodies (member templates included) are defined out-of-class, below the class in the header (templates) or in the .cpp (non-templates). Only trivial one-liners (`node_count()`-class accessors) may stay inline in the class (author 2026-08-17).
  - Comment tone: technical, concise, precise — never sensational. No all-caps emphasis (write "the whole schedule is derived", not "the ENTIRE schedule"; use *italics*-free plain phrasing — if a word needs stress, restructure the sentence so it doesn't). No exclamation marks, no marketing adjectives ("blazing", "powerful"), no meta-commentary about the repo or file structure (a comment explains the code and its contracts, not how the sample is packaged). State facts and invariants; let the content carry the weight. Dashes in code comments and in emitted message strings (fatal/assert/log/usage text) use a single hyphen `-`, not an em-dash (`—`) or the ASCII `--` em-dash convention; `--` is reserved for CLI flags (`--tests`).
